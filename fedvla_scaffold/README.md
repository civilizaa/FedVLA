# FedVLA 复现骨架

不装 MuJoCo、不装 torch，先把 FedVLA 的两个核心算法跑通。
目的：让你在决定投入前，用 10 分钟验证这套东西到底要写多少、难在哪。

## 现在能跑什么

```bash
python smoke_test.py
```

依赖只有 numpy。它会输出三组结果：

1. **DGMoE 双门控的稀疏度扫描**：改变专家自感知参数 `W_e` 的初始化尺度，观察平均每个 token 激活多少个专家。
2. **EDA 聚合权重**：验证权重每层求和为 1，并展示"两族均衡时权重几乎均匀"这个现象。
3. **一轮服务器聚合**：确认 trunk 参数能按 EDA 权重合并，且与 FedAvg 结果不同。

## 已经从这轮冒烟测试里挖到的两个发现

### 发现 1：`W_e` 的初始化尺度直接决定稀疏度，论文没交代

公式是 `se = sign(st - λ·W_e)`，`st` 是 K 路 softmax，均值约 `1/K`。
所以阈值 `λ·W_e` 必须与 `1/K` 同量级才有效：

| `W_e` 尺度（λ=0.5, K=8） | 平均激活专家数 |
|---|---|
| 0.00 | 8.00（全激活，等于没剪枝） |
| 0.10 | 4.54 |
| 0.20 | 3.30 |
| 0.80 | 1.71 |

论文报告激活密度约 1.22，但没有说 `W_e` 怎么初始化、训练中怎么演化。
**这是一个可以直接做的分析点**：稀疏度对 `W_e` 初始化的敏感性，
以及它如何影响论文声称的"计算效率提升"。

### 发现 2：EDA 是按"中心性"加权，不是按"簇"聚合

公式 `w_i ∝ Σ_j s_ij` 衡量的是客户端 i 与所有人的相似度之和。

- **两族均衡划分**（0/1 一族、2/3 一族）：权重 ≈ 0.249 / 0.249 / 0.251 / 0.251，
  几乎完全均匀 → **此时 EDA ≈ FedAvg，预期增益极小**。
- **存在横跨两族的客户端**：该客户端权重最高（0.29），
  而失去同族伙伴的客户端权重最低（0.18）。

也就是说，EDA 只惩罚"孤立"的客户端，不做"分簇后分别聚合"。
FedMVLA 的 MAFA（按本体分组聚合）在这一点上是更直接的方案。

**这给方向 A 提供了一个可证伪的假设，而不是空泛地说"EDA 更好"**：
在均衡的任务划分下，EDA 相对 FedAvg 的增益应当接近于零；
换成按簇聚合后增益才会显现。这个实验纯仿真就能做完。

> 以上两条都来自随机张量的 toy 实验，接上真实 HPT 后必须复验。

## 接真实模型的改动点

| 现在（numpy 骨架） | 换成（真实训练） |
|---|---|
| `dual_gate()` 的随机 token | HPT trunk 每层的 MHA 输出 token |
| `W_t / W_e / W_g` 随机初始化 | torch `nn.Parameter`，`λ=0.5` |
| `accumulate_counts()` | 每个 batch 统计激活次数，累积成 `V (L, K)` |
| `eda_weights()` | 服务器上按公式 7-9 算权重 |
| `aggregate_trunk()` | 只聚合 trunk；stem 与 head 保持个性化（原文 Figure 2） |
| 随机 trunk 张量 | HPT trunk 参数 |

## 纯仿真的两个简化（能省掉大量工程）

1. **IOSP 的 YOLOv8 检测可以跳过**。仿真器直接给出物体位置与状态真值
   （Meta-World 有 object states，LIBERO 有 BDDL 状态），
   不需要跑检测器，也不需要离线推理缓存。
   **代价**：你的 IOSP 退化成"基于真值的场景解析"，
   论文里必须写明这是仿真设定下的简化，并讨论真机没有真值时性能会下降多少。
   这个讨论本身是论文的一节内容。

2. **CLIP 部分保留成本低**。它只用来做目标/周围/背景的语言相似度分组与 top-k 选择，
   可以离线预计算一次存盘，训练时直接读，不占每轮算力。

## 接下来按顺序做

1. 装 MuJoCo + Meta-World，`pip install` 完先跑通内置示例。
2. 下载 HPT-Base（12.6M）权重，跑通单机行为克隆，记录显存与每 epoch 耗时。
3. 把本目录的 `fl_core.py` 换成 torch 版本，接到第 2 步的训练循环上。
4. 先做 2 客户端 FedAvg，确认非 iid 划分下确实掉点（复现"异构有害"这个前提）。
5. 再加 DGMoE + EDA，看是否出现 FedVLA > FedAvg 的趋势。

第 4 步跑不出掉点、第 5 步跑不出趋势，就停下来检查实现，不要继续加模块。
