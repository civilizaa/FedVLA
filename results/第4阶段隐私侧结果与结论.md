# FedVLA 第 4 阶段（隐私侧）结论：上行更新泄漏的是**动作标签**而非视觉观测；客户端级 DP 在此模型规模上"效用尽毁、隐私不保"

> 生成时间：2026-11-08 ｜ 实验台：异构划分 + MoE + 簇感知聚合（P3-C，`global_r49`）
> 威胁模型：诚实但好奇的服务器；攻击者拿到**被 DP 噪声污染后的**上行更新
> 攻击方法：DLG（Deep Leakage from Gradients），随机初始化，逐通路分别优化

---

## 一、一句话结论

FedVLA 的上行更新（trunk + normalizer + modalities_tokens）**泄漏的是客户端的私有动作序列**，
而不是视觉观测：攻击者能从 17.1M 维的共享主干梯度里把 8×4 的动作块**近乎完整地还原**
（余弦 0.97，rel_l2 0.24），却**完全无法还原视觉特征**（逐 patch 相关 0.03）。
更糟的是，**客户端级 DP 在这个模型规模上无法同时满足效用与隐私**：
噪声小到还能学习时（σ=1e-4）攻击几乎不受影响（cos 0.971 vs 无噪声 0.972）；
噪声大到开始伤害攻击时（σ=1e-2），共享主干的学习信号保真度已跌到 **0.024**——训练本身先废了。

**关于 H3（模态感知预算优于统一预算）的最终判定：被推翻，且对 DP 组合口径不敏感。**
三套等总 ε 的分配方案（uniform / 先验模态感知 / 按实测可攻击性重分配）在动作泄漏强度上
**几乎无差别**（σ=1 时三者 cos 全是 0.934），但在共享主干的保真度上
**modal_rev < modality < uniform 在全部 5 个 σ 点上严格成立**
（σ=1e-4：0.734 < 0.863 < 0.924）⇒ **按模态分预算在"上行联邦 + 并行组合 DP"下
结构性地损害真正外传的通道**，而不是改善它。

## 二、三个必须先讲清楚的架构事实（全部实测，非推测）

### 2.1 反演目标是 ResNet 特征图，不是像素

Meta-World 的 zarr 里 `image` 存的是 **ResNet 提取的 512 维特征**：

| 证据 | 内容 |
|---|---|
| zarr 数组 | `image (7204, 1, 49, 512) float32`，取值范围 **[0, 15.77]** |
| stem 权重 | `stems.<d>_image.net.0.weight` = **(128, 512)** ⇒ image MLP 输入维 512 |
| stem 结构 | `net: 512→128→256`，`cross_attention: 16 个可学习 token  attend  49 个 patch` |

⇒ 反演潜变量 x̂ 的形状是 **(1, 1, 49, 512)**（49 个 patch × 512 维），
**不能套用像素域的 sigmoid 参数化**，指标也要换成**逐 patch Pearson 相关**。
论文里"重建出来的图"因此是 **7×7 空间 patch 热力图**（对 512 通道取均值），不是照片。

### 2.2 语言通路在本配置下不存在

实测 `policy.modalities = ['image', 'state']`，`cfg.stem` 无 language 键，
且在 eval 模式（关 dropout、前向确定性）下：

```
loss(无语言) = 0.26731178
loss(有语言) = 0.26731178
|Δ|          = 0.000e+00
```

HPT 的 T5 语言嵌入（zarr 里 `language (N, 16, 768)`）**根本没有被策略消费**。
⇒ 本文的模态敏感度分析覆盖 **视觉 / 状态 / 动作** 三通路，论文如实写明，
不虚构"语言通路"。

### 2.3 上行里没有"模态专属"的共享参数

`aggregate.py` 的 `_is_shared_param` 口径：上行 = `trunk.*` + `normalizer.<domain>` +
`modalities_tokens.*`，而 `stems.*` / `heads.*` 是**个性化参数、留在本地**。
实测各组在上行里的构成：

| 组 | 张量数 | 参数量 | 是否上行 |
|---|---|---|---|
| shared（trunk 主体） | 368 | 17.1346M | ✅ **唯一的大通道** |
| state（normalizer.state + modalities_tokens.state） | 11 | 0.5669M | ✅ |
| action（normalizer.action + heads） | 10 | 0.1031M | ✅ |
| vision（stems.image + modalities_tokens.image） | 9 | 0.6273M | ❌ stems 不上行 |

另外：`modalities_tokens` 虽然 `use_modality_embedding: true`，但在 `preprocess_tokens`
里**从未被引用** ⇒ 是死参数、无梯度、不构成泄漏通道。

⇒ **架构性结论**：FedVLA 把模态专属参数挡在设备内，服务器唯一能拿到的大通道是
**模态无关的共享主干**。这既是隐私上的天然优势，也直接决定了 DP 预算分配的
作用方式（见第五节）。

## 三、逐通路敏感度（消融法）

**方法**：把某一条通路的输入换成**另一条轨迹**的输入（其余保持真实），重算梯度 g_m，
定义两个互补指标：

- **相对变化** `D_m = ‖g_full − g_m‖₂ / ‖g_full‖₂`（幅度变化）
- **方向泄漏强度** `1 − cos(g_full, g_m)`（方向变化，∈[0,2]；0 = 完全不依赖该通路）

⚠️ donor 必须**跨 episode**：zarr 里 7204 步 = 100 集 × ~72 步，
**相邻索引是同一条轨迹的相邻时间步**，动作几乎相同 ⇒ 用 `idx+1` 会测出 D_action = 0（假零）。

| 通路 | D_m（幅度）样本 0 / 1 / 2 | D_m 均值 | 1−cos（方向泄漏）样本 0 / 1 / 2 | 1−cos 均值 |
|---|---|---|---|---|
| 视觉（输入） | 3.82 / 7.85 / 5.43 | **5.70** | 0.760 / 0.780 / 0.882 | 0.81 |
| 状态（输入） | 1.76 / 3.55 / 5.37 | 3.56 | 0.136 / 0.814 / 0.934 | 0.63 |
| **动作（标签）** | 2.24 / 1.79 / 1.29 | 1.77 | **1.358 / 1.014 / 0.676** | **1.02** ← 最强 |

⚠️ **两个指标的可信度不同，必须分开说**（这是 3 样本后才看清的）：

- **方向泄漏强度 `1−cos` 的排序在三个样本上完全一致**（action > image > state），
  且 action 始终最高 ⇒ **结论稳健**。它与"攻击者能从梯度里读出什么"直接对应，
  是本章最可靠的排序依据。
- **幅度敏感度 `D_m` 只有"image 最高"这一条稳定**；
  action 与 state 的相对顺序**随样本翻转**（样本 0 是 action > state，样本 1/2 是 state > action）
  ⇒ **D_m 不能单独用来给通路排序**（此前基于单样本给出的 image > action > state 排序不成立）。

**关键洞见：敏感度 ≠ 可攻击性。**
视觉通路让梯度的**幅度**变化最大（均值 5.70 倍，3 个样本均最高），
但**方向**仍保留 19% 重合；而动作通路让梯度的**方向几乎完全翻转**
（样本 0 的 cos = −0.358，1−cos = 1.358 > 1）。
对攻击者而言，"方向里编码了什么"才是信息量 ⇒ **动作才是真正的泄漏通道**。

> 推论：**DP 预算应按"实际泄漏严重度"（方向泄漏）分配，而不是按"输入敏感度"（幅度）分配。**
> 第五节的 `modality_rev` 方案正是按这个修正后的依据重分配预算的。

## 四、梯度反演攻击：什么能被还原，什么不能

攻击设定：服务器只拿到 **trunk 梯度**（368 张量 / 17.135M 参数），用 DLG 联合优化候选
潜变量与候选动作，使候选上的 trunk 梯度与观察到的梯度方向一致。

**两个实现上的硬约束（踩过的坑）**：

1. **梯度匹配必须取 key 交集**。MoE 的 top-k 路由**随输入变化** ⇒ 候选前向的梯度张量集合
   是服务器收到的梯度集合的真子集（实测 15.82M vs 17.13M，差 1.32M）。
   服务器只收到"被激活专家"的梯度，攻击者自然也只能用交集。
2. **注意力必须走数学后端**。PyTorch 默认的
   `aten::_scaled_dot_product_efficient_attention` **没有二阶导实现**，
   DLG 的 `create_graph=True` 会直接崩。必须全局关掉 flash / mem-efficient。

**结果（随机初始化，即诚实攻击者：他只有梯度，不知道这条样本的内容）**：

| 反演目标 | 潜变量维度 | 无噪声重建 | 随机基线 | 结论 |
|---|---|---|---|---|
| **动作序列** | 32 | **cos 0.970 / rel_l2 0.24** | 0.000 | ✅ **近乎完整还原** |
| 状态向量 | 39 | cos 0.185 / rel_l2 3.70 | 0.000 | ❌ 失败 |
| 视觉特征图 | 25088 | corr 0.027 / rel_l2 1.31 | 0.001 | ❌ 失败 |

### 4.1 为什么动作能被还原、观测不能？—— 标签 vs 输入

动作和状态的潜变量维度相近（32 vs 39），结果却天差地别。原因是**泄漏路径的长短**：

- **动作是"标签"**：它直接进入 loss 的残差项，`∂L/∂features ∝ (pred − y)`。
  标签的信息沿着最短路径流进梯度，**信号集中、方向明确** ⇒ 32 维的欠定问题被轻易解出。
- **视觉/状态是"输入"**：它们要穿过整个 17.1M 维共享主干才能影响 loss，
  在梯度的 17.1M 维里留下的痕迹被彻底稀释 ⇒ 高维欠定问题无法求解。

⇒ **上行梯度泄漏的是标签，不是观测。** 这与梯度反演文献的经典结论一致，
但在 VLA 场景下有一个重要推论：**只要策略用动作做监督，客户端的私有动作就必然泄漏**。

### 4.2 视觉反演失败是"维度诅咒"，不是"优化不足"（对照组）

为排除"步数不够 / 学习率不对 / 匹配集选错"的解释，做了 4 组对照：

| 组 | 匹配集 | 步数 | lr | match loss（攻击目标） | rel_l2（重建误差） |
|---|---|---|---|---|---|
| V1 | dense | 300 | 0.05 | → 0.0068 | **1.3168** |
| V2 | dense | 300 | 0.01 | → 0.0068 | **1.3168** |
| V3 | all（368 张量） | 300 | 0.05 | → 0.0015 | **1.3142** |
| V4 | dense | 600 | 0.05 | → 0.0015 | **1.3168** |
| — | — | — | — | 随机基线 1.0 | 1.0 |

攻击目标被优化到 **match loss < 0.002**（比随机低 3 个数量级），**但重建误差始终钉在
rel_l2 ≈ 1.31**。⇒ 梯度映射存在**大量退化解**：不同的 x̂ 给出几乎相同的梯度。
视觉观测在共享主干的梯度映射下**不可辨识**，这是 17.1M 维共享主干带来的维度诅咒，
**与算力或优化超参无关**。

## 五、DP 预算与 H3：等总预算下的两套分配

### 5.1 为什么自变量必须是 σ 而不是 ε

trunk 有 17.1M 参数，客户端级 DP 的噪声总范数 = σ·C·√17.1M = **σ·4139**（C=1）。
若 σ=1（对应 ε≈1），噪声范数 4139 远大于裁剪后的信号范数 1 ⇒
**任何 ε∈[1,32] 的配置都落在噪声地板上**，"ε 越大越容易被反演"的规律根本画不出来。
真正的转折在 **σ≈1e-4**（对应 ε≈1e5~1e9）。
⇒ 论文的横轴用 **σ（对数刻度）**，并在标注里给出对应的 ε。

### 5.2 两套分配的定义（总 ε 相同）

并行组合语义（各组参数互不相交）：总 ε = **max_m ε_m**。

- **uniform（统一预算）**：所有组同一个 σ。
- **modality（模态感知）**：ε_m = ε_total · w_m / w_max，
  先验敏感度权重 w = {vision 0.50, state 0.15, action 0.10, shared 0.25}。
- **modality_rev（按实测可攻击性重分配，事后分析）**：
  w = {action 0.50, vision 0.30, state 0.10, shared 0.10}，
  依据是第三节测到的方向泄漏强度排序 action > image > state（**与先验假设相反**）。

同一个 σ_ref 下，两套方案的**总 ε 完全相同**（已写成单元测试断言）⇒ 对比是等预算的。

### 5.3 组合语义口径的敏感性（必须诚实说明）

H3 的结论**依赖 DP 的组合口径**，论文必须写清楚：

- **口径 A（max 在全部本地组上取）**：锚点是不上行的 vision 组 ⇒
  外传的 shared 只拿 0.5·ε_total ⇒ **σ_shared 比统一预算大 1.41×** ⇒ 对实际泄漏通道保护更强。
- **口径 B（max 只在上传组上取）**：锚点是 shared ⇒ 模态感知与统一预算
  **对 trunk 完全等价** ⇒ H3 不成立。

本文采用口径 A，理由是：**DP 保护的对象是客户端的私有数据，而不是"已经离开设备的东西"**。
stems/heads 是客户端私有的个性化参数（编码了本地数据），DP 噪声加在它们上保护的是
本地训练过程的隐私；把总预算锚在不上传的组上，就能"免费"收紧真正外传的共享主干。
同时本文**同时报告两者的效用代价**，让读者自行判断。

### 5.4 实测：口径 A 下 H3 **被推翻**，且机制清晰（本章最重要的负结果）

同一 σ_ref 下两方案**总 ε 完全相同**（等预算），但**共享主干的信噪比系统性更差**：

| σ_ref | 方案 | 总 ε | ε_shared | σ_shared | SNR_shared | 保真度(shared) |
|---|---|---|---|---|---|---|
| 1e-4 | uniform | 5.0e9 | 5.0e9 | 1.00e-4 | 17.90 | **0.9240** |
| 1e-4 | modality | 5.0e9 | 2.5e9 | 1.41e-4 | 12.66 | 0.8630 |
| 1e-3 | uniform | 5.0e7 | 5.0e7 | 1.00e-3 | 1.79 | **0.2350** |
| 1e-3 | modality | 5.0e7 | 2.5e7 | 1.41e-3 | 1.27 | 0.1686 |
| 1e-2 | uniform | 5.0e5 | 5.0e5 | 1.00e-2 | 0.179 | **0.0244** |
| 1e-2 | modality | 5.0e5 | 2.5e5 | 1.41e-2 | 0.127 | 0.0173 |
| 0.1 | uniform | 4873 | 4873 | 1.00e-1 | 0.0179 | **0.0026** |
| 0.1 | modality | 4873 | 2436 | 1.40e-1 | 0.0128 | 0.0019 |
| 1 | uniform | 16.6 | 16.6 | 1.00 | 0.0018 | **0.0005** |
| 1 | modality | 16.6 | 8.27 | 1.49 | 0.0012 | 0.0004 |

**H3（"模态感知预算优于统一预算"）在口径 A 下被推翻：模态感知方案在每一个 σ 点上
共享主干的保真度都比统一预算更低。** 机制链条很短：

1. 先验权重把最大 ε（= ε_total）分给了 **vision** 组；
2. 但 **vision 组（stems/heads）根本不上传**——服务器永远看不到它；
3. 于是**真正外传的 shared 只拿到 0.5·ε_total**，σ_shared 被放大 **1.41×（=√2）**；
4. 信噪比整体下滑 1.41×，学习信号被更早摧毁 ⇒ **效用更差，而隐私没有换来任何好处**。

⇒ **"按模态敏感度分配 DP 预算"在纯上行联邦里会误导预算**：
把预算锚在最敏感却**不出站**的数据上，等于把预算浪费在服务器看不到的地方，
代价全部落在真正出站的共享主干上。

**口径 B（max 只在上传组上取）**则相反：锚点变成 shared ⇒ 模态感知与统一预算
**对 trunk 完全等价** ⇒ H3 同样不成立（无差异）。

**综合判定：H3 在两种口径下都不成立。** 但失败的原因不是"模态感知思想无效"，
而是**权重的依据选错了**——第三节实测表明，
真正该看的是**方向泄漏强度**（action > image > state，3 样本一致），
而不是**幅度敏感度**（image 最高，但 action/state 排序不稳）。
于是补做第三套方案 `modality_rev`：按前者重分配权重
（action 拿满 ε_total ⇒ shared 只拿 0.2·ε_total），
用来检验"依据修正后的 H3"是否成立。**实测结果见 5.5：仍然不成立，且更糟。**

### 5.5 modality_rev 的实测结果：修正依据后 H3 依然被推翻（且更糟）

⚠️ 本节是**实测**（`--dp-steps 50`，总 ε 与 uniform/modality 严格相等），
不是推演。此前在手稿里写的"σ_shared = 0.447 σ_ref（比统一预算更小）"是**错的**，
错在把 σ 与 ε 的关系当成正比；在固定 (δ, steps) 下 RDP accountant 给出的是
**ε ∝ 1/σ²**（即 σ ∝ 1/√ε），所以 ε_shared 缩小 5 倍 ⇒ **σ_shared 放大 √5 ≈ 2.236 倍**。
实测值与 √5 吻合，说明机制判断正确、符号写反了。

**实测预算分配（σ_ref = 1e-4，总 ε = 5.0e9，三方案完全相等）**：

| 方案 | ε_shared | σ_shared | σ_shared/σ_ref | SNR_shared | **保真度(shared)** |
|---|---|---|---|---|---|
| uniform（统一预算） | 5.0e9 | 1.000e-4 | 1.000× | **17.90** | **0.9240** ← 最好 |
| modality（口径 A，先验权重） | 2.5e9 | 1.414e-4 | 1.414× | 12.66 | 0.8630 |
| **modality_rev（实测可攻击性排序）** | **1.0e9** | **2.236e-4** | **2.236×** | **8.01** | **0.7339** ← **最差** |

**五个 σ 点全部一致，modality_rev 的共享主干保真度在每个点上都最低**：

| σ_ref | uniform 保真度 | modality 保真度 | modality_rev 保真度 |
|---|---|---|---|
| 1e-4 | **0.9240** | 0.8630 | 0.7339 |
| 1e-3 | **0.2350** | 0.1686 | 0.1076 |
| 1e-2 | **0.0244** | 0.0173 | 0.0110 |
| 0.1 | **0.0026** | 0.0019 | 0.0013 |
| 1 | **0.0005** | 0.0004 | 0.0003 |

**而隐私侧没有换来任何补偿**：三种方案的动作重建 cos 几乎相同
（σ_ref=1e-4 时 0.9709 / 0.9722 / 0.9739；σ_ref=1 时三者都是 0.934）。
modality_rev 在"保护共享主干"和"保护动作"两件事上**都没有优势**。

**机制解释（本章最干净的一条结构性结论）**：
并行组合语义下总 ε = **max_m ε_m**，即**权重最大的那组是锚点**，其余组按比例缩水。
- `modality`：锚点是 vision（w=0.50）→ 但 vision **根本不上传** ⇒ 真正外传的 shared
  只拿 0.5·ε_total，σ_shared 放大 1.414×。
- `modality_rev`：锚点是 action（w=0.50）→ action 确实是外传的，但 **shared 同样只拿
  0.2·ε_total**（w=0.10 vs w=0.50）⇒ σ_shared 放大 **2.236×**，比 modality 还糟。

⇒ **结构性结论：等总 ε 下，只要把预算分给别的组，真正外传的 shared 组就会被削弱。**
H3 之所以失败，不是权重没选对，而是"按模态分配预算"这件事在
**上行联邦 + 并行组合 DP** 的语义下**结构性地注定失败**：
锚点组拿走全部 ε，其余组（含 shared）一律按比例缩水，
而 shared 恰恰是服务器唯一能看到的通道。
（若改成"只在上传组之间分配"（口径 B），锚点落回 shared ⇒ 与 uniform 完全等价 ⇒ H3 仍是"无差异"，
两种口径下 H3 都不成立，结论对口径不敏感。）

## 六、隐私-效用的完整权衡（本章最重要的表）

见 `privacy_table.md` 与 `privacy_budget_table.md`。核心读数（3 样本均值，
三种预算方案**总 ε 完全相同**，可直接横向比）：

| σ_ref | 总 ε | 保真度(shared)<br>unif / modal / **modal_rev** | 动作重建 cos<br>unif / modal / **modal_rev** | 状态 cos<br>(uniform) | 视觉 corr<br>(uniform) |
|---|---|---|---|---|---|
| clean（无 DP） | — | 1.000 / — / — | 0.972 / 0.972 / 0.974 | 0.301 | 0.026 |
| 1e-4 | 5.0e9 | **0.924** / 0.863 / 0.734 | 0.971 / 0.972 / 0.974 | 0.331 | 0.024 |
| 1e-3 | 5.0e7 | **0.235** / 0.169 / 0.108 | 0.974 / 0.975 / 0.973 | 0.254 | 0.026 |
| 1e-2 | 5.0e5 | **0.024** / 0.017 / 0.011 | 0.956 / 0.946 / 0.943 | 0.444 | 0.024 |
| 0.1 | 4873 | **0.0026** / 0.0019 / 0.0013 | 0.938 / 0.937 / 0.936 | 0.079 | 0.009 |
| 1 | 16.6 | **0.0005** / 0.0004 / 0.0003 | 0.934 / 0.934 / 0.934 | −0.014 | 0.002 |

读这张表最关键的一行是 σ_ref=1：**三方案的动作泄漏强度完全相同（cos 0.934），
而共享主干的保真度差了 1.7 倍**（0.0005 / 0.0004 / 0.0003）⇒
**预算分配方案在"隐私"维度上毫无差别，差别全落在"效用"维度上，而且是负方向的差别。**

**三个互锁的结论**：

1. **σ 越小（噪声越弱）**：共享主干学习信号保真度越接近 1，
   但动作重建 cos 也越接近无噪声值 ⇒ **隐私预算形同虚设**。
2. **σ 越大（噪声越强）**：保真度断崖式下跌（σ=1e-2 时已仅 **0.024**，
   σ=1 时 **0.0005**），而动作重建**下降极慢**
   （噪声放大 **10⁴ 倍**，cos 只从 0.971 掉到 0.934，降幅 3.8%）。
3. ⇒ **客户端级 DP 在 FedVLA 上是"效用尽毁、隐私不保"的最坏组合**：
   在有用的 ε 区间（ε≈16~5000）内保护不了动作泄漏；
   而把噪声加到能保护动作的程度（σ=1，ε=16.6），联邦学习本身已经失效
   （共享主干学习信号只剩 0.05%）。

**机制解释**：动作是**标签**，它的信息以"残差项"的形式**直接**进入梯度，
信号集中、方向明确 ⇒ 少量噪声就能抹掉它；
而把噪声放大到破坏学习信号的程度，需要把 σ 提高约 4 个数量级
（噪声总范数 = σ·√17.1M = σ·4139），此时动作方向依然完好。

**对照（须诚实说明的两处细节）**：

- **视觉**：从一开始就失败（corr 始终 ≈ 0.002–0.026，贴着随机基线）⇒ 高维输入不可辨识。
- **状态**：整体随噪声崩塌（σ=0.1 起掉到 0.079，σ=1 时 −0.014 ⇒ 无泄漏），
  **但 σ=1e-2 处出现非单调的虚高**（cos 0.444 > 无噪声的 0.301）。
  这不是"噪声让泄漏变强"，而是**噪声主导了梯度方向**后，攻击者的候选变量去拟合噪声方向
  造成的伪相关 —— 此时 cos 衡量的是"拟合噪声"而非"还原真实状态"。
  状态泄漏本身在 clean 下也只有 0.301，本来就不构成实质威胁。

⇒ **DP 噪声只对"高维输入型泄漏"有效，对"标签型泄漏"几乎无效**；
真正的风险点是**标签（动作）通道**，它必须靠架构或协议层面解决（见第八节）。

## 七、局限与诚实记录

1. **效用侧是代理指标**。本章用"共享主干学习信号保真度"cos(干净梯度, 加噪梯度) 代替
   任务成功率，因为它无需跑 MuJoCo 评估即可大规模扫描。代价：它衡量的是**上行更新里
   学习信号被破坏的程度**，不等于任务成功率。**这是本章最需要补强的地方**。
2. **反演攻击只覆盖 DLG**。没有对比 GradInversion / iDLG 等更强攻击者，
   所以"动作被完整还原"是**下界**（真实泄漏可能更严重）。
3. **样本量**：隐私侧用 3 个样本 × 200 步 DLG，没有做多 seed 显著性检验
   （通信侧是 3 seeds × 20 rollouts）。趋势方向清晰，但绝对值需谨慎解读。
4. **语言通路缺席**（见 2.2），三通路而非路线图原设的四通路。
5. **DP 施加在"客户端本地全部参数"上**，服务器观察其 trunk 子集；
   若只对上行的共享部分加噪，则上行里只剩一个模态组，"模态感知"在 FedVLA 上是空的。
6. **σ 与 ε 不是线性反比（本次差点栽在这里）**。固定 (δ, steps) 时 RDP accountant 给出
   **ε ∝ 1/σ²**（σ ∝ 1/√ε）。手稿曾按 "ε_shared 缩小 5 倍 ⇒ σ_shared 缩小 5 倍"
   推演出 "0.447 σ_ref"，符号完全写反；实测是 **2.236 σ_ref = √5**（与 √5 精确吻合）。
   ⇒ 任何跨预算方案的定量对比，**必须读实测的 σ 分配表**（`privacy_budget_table.md`），
   不能靠 ε 的比例手推 σ。
