## 一、一句话结论（隐私侧已锁定；通信侧修正版重跑完成）

FedVLA 的上行更新（trunk + normalizer + modalities_tokens）**泄漏的是客户端的私有动作序列**，
而不是视觉观测：攻击者能从 17.1M 维的共享主干梯度里把 8×4 的动作块**近乎完整地还原**
（余弦 0.97，rel_l2 0.24），却**完全无法还原视觉特征**（逐 patch 相关 0.03）。
更糟的是，**客户端级 DP 在这个模型规模上无法同时满足效用与隐私**：
噪声小到还能学习时（σ=1e-4）攻击几乎不受影响（cos 0.971 vs 无噪声 0.972）；
噪声大到开始伤害攻击时（σ=1e-2），共享主干的学习信号保真度已跌到 **0.024**——训练本身先废了。

**H3 的最终判定：被推翻，且对 DP 组合口径不敏感。** 三套等总 ε 的预算分配
（uniform / 先验模态感知 / 按实测可攻击性重分配 modality_rev）在动作泄漏强度上
**几乎无差别**（σ=1 时三者动作 cos 全是 0.934），但共享主干保真度上
**modal_rev < modality < uniform 在全部 5 个 σ 点严格成立**
（σ=1e-4：0.734 < 0.863 < 0.924）⇒ **按模态分预算在"上行联邦 + 并行组合 DP"下
结构性地损害真正外传的通道**，而不是改善它。

**方法论上的自我补强（4.6，✅ 已完成）**：上述"保真度"是**代理指标**，不是任务成功率。
为避免整章建立在一个未经检验的代理上，补做了**同一 σ 上的真实任务成功率**
（真实 MuJoCo 评估，3 seeds × 20 rollouts），与代理指标逐点对表 ⇒
第四章已从"只有代理指标"升级为"**代理指标 + 真实指标 + 两者可比**"。

🔴 **补强的结论比预想更尖锐**：在**最小**的 σ=1e-4（噪声/信号比 0.41）上，
**真实任务成功率已经是 0.000（3 seeds 全 0），而此时代理保真度仍有 0.924**（几乎无损）。
⇒ **代理指标在这个方向上"过于乐观"，没能预警效用崩塌**；
⇒ 结合 σ=1e-2 时保真度已崩到 0.024，可得一个**双向失效**的结论：
**代理保真度既不能保证"真实效用还在"（低 σ 端漏报伤害），也不能保证"隐私还保得住"（高 σ 端）。
真实任务成功率与隐私侧指标必须同时测量，代理指标不能替代其中任何一个。**（详见 4.6.3）

**通信侧（第三节，修正版重跑后）**：两条结论，且第二条是本轮最重要的发现。

1. **客户端级上行丢包（0~75%）对 task3 成功率无可分辨影响**：三个丢包组相对基线
   的差异为 −10.0 / +20.0 / +10.0 pp，Welch t 检验（df=2）p = 0.49 / 0.22 / 0.49，**全部不显著**
   ⇒ 异构 + MoE + 簇感知聚合对"设备掉线"是鲁棒的（但本实验功效只够排除 >30 pp 的效应）。
2. **压缩才是真正的瓶颈，而且"权重保真度"会骗人**：int8_g 把上行流量压到 1/4，
   **权重级相对误差只有 0.44%**，却把成功率从 0.717 打到 **0.000**。
   取证结论（3.4）：**per-group(64) 对称量化把小动态范围张量（normalizer 的 scale/offset）
   的小值全部 round 到 0**，使 39 维状态输入退化到 **16 维有效**（干净模型 39/39），
   策略对状态"失明" ⇒ 成功率归零。
   **⇒ 通信压缩方案必须显式排除"归一化统计量"这类小动态范围缓冲区，
   且必须用任务级指标（而非权重 MSE）验证压缩方案。**

## 二、实验设计

### 2.1 实验台与通信侧配置

| 项 | 取值 | 理由 |
|---|---|---|
| 实验台 | 异构划分 + MoE(top-k E=8,k=2) + **簇感知聚合**（= P3-C） | 论文第4章要回答"**我们的方法**在链路受损下还站不站得住" |
| 评估任务 | **task3**（button-press-topdown-v2） | task1/task2 成功率被压到 0（地板效应），task3 是唯一有信号的域 |
| 轮数 | **50**（与第3阶段 P3-C 对齐） | 25 轮下基线落在地板（c_drop00 task3=0.017、c_int8=0.000），曲线零区分度 |
| 丢包口径 | **fixed**（每轮固定丢 k 个 + 轮换） | Bernoulli 在 n=4/rate=0.1 时可能连续 50 轮不丢，损伤被随机性稀释 → 得出"丢包无影响"的假结论 |
| 量化口径 | `comm_analysis.py` 同源（int8_g / int4_g / bit1） | 与门2 的通信成本表同源，可交叉引用 |
| 统计 | 3 seeds × 20 rollouts，报均值 ± 95% CI | df = n−1 = 2 ⇒ t₀.₉₇₅ = 4.303 |

### 2.2 隐私侧配置

| 项 | 取值 |
|---|---|
| 反演目标 | 视觉 = 49×512 ResNet 特征（逐 patch Pearson）；动作 = 8×4 序列（余弦）；状态 = 39 维（余弦） |
| 初始化 | **随机**（`FEDVLA_INV_INIT=random`），"真值+噪声"只作先验上界对照 |

| 预算方案 | uniform / modality（口径 A）/ modality_rev（按实测方向泄漏排序） |

### 2.3 DP 效用实验配置（真实任务成功率 ↔ 代理指标交叉验证）

> **为什么必须做**：第四节的隐私侧原本只有**代理指标**（共享主干学习信号保真度）。
> 论文只报代理指标，委员会一定会问"那真实任务还能不能学会？"
> ⇒ 必须补一条**真实任务成功率**随 σ 的曲线，与代理指标在**同一个 σ** 上对表。

| 项 | 取值 | 理由 |
|---|---|---|
| 实验台 | 与通信扫描**完全一致**的 P3-C（异构 + MoE + 簇感知，50 轮） | 唯一变量 = 上行 DP 噪声 σ ⇒ 干净基线可直接复用 `c_drop00` |
| 加噪位置 | **客户端上行前**（改写客户端 `model.pth` 的共享参数） | 威胁模型是"服务器观察上行"。加噪做在客户端侧 ⇒ **完全不需要改 `aggregate.py`**（它正被通信扫描占用） |
| 加噪形式 | `Δ·min(1, C/‖Δ‖₂) + N(0,(σC)²)`（**per-coordinate**） | DP-FedAvg 标准形式；上行 = 非 `stems.*`/`heads.*` 的全部键（个性化参数不上行，不加噪） |
| C 标定 | C = ‖Δ‖₂ **中位数**（跑 2 轮干净训练实测） | ε 只依赖 σ（ε ∝ 1/σ²），C 是纯效用旋钮；取中位数让裁剪真正生效 |
| σ 网格 | **1e-4 / 1e-3 / 1e-2** | 与隐私侧 uniform 方案**完全一致** ⇒ 真实指标与代理指标可在同一 σ 上对表 |
| 噪声/信号比 | **σ·√d**（d≈17.1M ⇒ √d≈4134） | σ=1e-4 → 0.41（与信号同量级）；1e-3 → 4.1；1e-2 → 41 |
| ε 口径 | δ=1e-5，q=1/4（4 客户端），steps=50 | 与隐私侧同一个 RDP accountant ⇒ ε 直接可比 |
| 评估 | task3，3 seeds × 20 rollouts | 与通信侧同口径 |

> 🔴 **一个曾经栽进去的坑（已由离线单元测试抓出）**：DP 噪声是**逐坐标**的，
> 所以总噪声范数 = σ·C·√d，而信号范数 = C ⇒ **噪声/信号比 = σ·√d**，
> **不是** σ。初版设计误以为 σ 就是噪声/信号比，据此把网格定成 {0.01, 0.1, 1.0}，
> 实际噪声是信号的 41~4134 倍 ⇒ 整个网格选错量级。
> 修正后与隐私侧网格对齐（见 `federated/test_dp_noise_client.py`，本地+云端各跑一遍，5 项全通过）。
> **教训：新写的实验代码先离线单测**——5 分钟的单测省下 6 小时算力。

#### 3.4.1 旧判定错在哪

11-18 的判定是：int8 的相对误差只有 0.005（0.5%），"物理上不可能把成功率从 0.75 打到 0"
⇒ 判为接线/统计故障；bit1 误差 0.557 ⇒ 判为真实效应。
（以上为 **11-18 当时的离线单测值**；本轮修正版重跑的实测 `quant_rel_err_max`：
int8 = 0.00443、int4 = 0.02519、**bit1 = 0.77047** ⇒ bit1 的"真实效应"判断本轮依然成立。）

**错误在于把"权重张量的平均相对误差"当成了"策略是否被破坏"的判据。**
本轮在同构重跑 + 取证之后，这条判据被证明是**不成立**的：

| # | 证据 | 数值 / 出处 |
|---|---|---|
| ① | 权重级误差**极小** | int8_g `quant_rel_err_max` = **0.0044**、`quant_drift` = 0.000205（**逐轮下降、无累积**）；int4_g = 0.0252 / 0.000361｜`comm_report_r49.json` |
| ② | 但成功率**仍是 0** | int8 / int4 / bit1 各 3 seeds 全 0｜`eval_c_int*_*.log` |
| ③ | 清零**不是均匀分布**，且**客户端权重比聚合模型严重一个量级** | 同一份权重自比对：`c_int4` 的 client0 权重量化清零 **8.168%**（int8）/ **8.189%**（int4），而 P3-C 聚合全局模型后验量化只清零 **0.463%**；清零最集中的是 **14 个** `trunk.trunk.blocks.*.attn.in_proj_weight`（768×256），**每张量 15.5~16.5% 的元素被清零**，而该张量的相对误差只有 **0.035%**｜`cf_forensics.py` / `cf_quant_variant.py` |
| ④ | 清零**可精确复现** | 把**未量化**的客户端权重用同一 scheme 再量化一次 ⇒ 零掩码与 checkpoint **完全一致**（normalizer 全部张量 mask 一致、maxdiff=0）｜`cf_forensics.py` Q2 |
| ⑤ | 被清零的参数**在推理路径上** | `run_eval.py`: `init_domain_head(domain, None, ...)` → normalizer 空建 → `policy.load_model(model.pth)`（strict=False）⇒ **评估用的就是 checkpoint 里那份被量化损伤的 normalizer**；`normalizer._normalize(forward=True)` = `x*scale + offset`｜HPT 源码 |
| ⑥ | 信息**真的丢了** | scale 被清零的维度 ⇒ 归一化输出恒为 offset。量化后 **task3 的 39 维状态只剩 16 维有效**（task1 8/39、task2 22/39）；干净模型 **39/39**｜`cf_blind.py` |
| ⑦ | 现有量化自检**测不出来** | 自检只看 NaN/Inf 与整体相对误差阈值 ⇒ int8（0.44%）顺利通过 ⇒ 不会中止 ⇒ 静默产出"全 0 曲线" |

> 🔴 **一个必须写进论文的口径警示**：同样一个 `int8_g`，
> **作用在客户端本地权重上会清零 8.168% 的元素，作用在聚合后的全局模型上只清零 0.463%**
> （差 **17.6 倍**），而两者的相对误差指标却几乎一样（**0.44% vs 0.49%**）。
> ⇒ **用"对聚合模型做后验量化"来评估联邦压缩方案的安全性，会严重低估真实风险。**
>
> ⚠️ **但这个 17.6 倍不能简单归因给"量化发生在哪一步"** —— 11-22 补了一个**步长对照**实验
> （`cf_p3c_int8_cs`）：拿**客户端权重的 per-group absmax** 去量化**聚合全局模型**，
> 清零率仍只有 **0.494%**（几乎不变）。
> ⇒ **步长来源不是主因；主因是权重自身的值分布**：
> 客户端本地训练后的权重里有大量**接近零的小权重**（SGD 稀疏化），
> 而 **FedAvg 的加权平均会把这些小值填平**，使聚合模型的分布更集中 ⇒ 步长更紧 ⇒ 清零更少。
> ⇒ 正确的表述是：**"上行量化作用在稀疏的客户端权重上"才是真正危险的组合**，
> 而这恰恰是联邦学习的默认形态（客户端本地训练 → 上传本地权重）。

#### 3.4.2 机制（**物理事实成立，但归因推论已被 3.4.4 / 3.4.6 推翻**）

> ⚠️ **读法提醒（必读）**：本小节描述的**清零事实全部实测成立**（哪些张量、多少维被清零）；
> 但由此推出的**归因**（"状态维度坍缩 ⇒ 策略失明 ⇒ 成功率必然归零"）**已被推翻** ——
> 3.4.4 的后验消融显示：**只**量化 normalizer（`cf_p3c_int8_norm`，normalizer 张量清零 **16.5%**）
> 反而是 **0.733（无损）**；**只**量化 trunk 是 0.750（无损）。
> ⇒ **清零是伴随现象，不是元凶**；真正的机制见 **3.4.6**。

per-group(64) 对称量化的步长由 **group 内 absmax** 决定：
`scale_g = absmax_g / qmax`，`q = clamp(round(x / scale_g))`。
**凡是绝对值小于半个步长的元素，量化指数直接 round 到 0** —— 这不是"精度损失"，是"元素被删除"。

**两类张量被"整片清零"，且都恰好是信息通道**：

| 张量 | 维度 | absmax | int8 清零 | int4 清零 | 后果 |
|---|---|---|---|---|---|
| `normalizer.task1.state.scale` | 39 | 3655.81 | 28 维 | **31 维** | 状态输入维度坍缩 |
| `normalizer.task3.state.scale` | 39 | 28.40 | — | **23 维** | 同上 |
| `normalizer.task1.state.offset` | 39 | 592.58 | — | 21 维 | 同上 |
| `normalizer.*.action.*` | 4 | 1.0~3.3 | 0 维 | 0 维 | 动作反归一化没坏 |
| `trunk.*.attn.in_proj_weight` ×14 | 768×256 | 重尾 | **15~16% 元素** | 15~16% 元素 | 注意力输入投影被"稀疏化" |

- **归一化统计量**：动态范围极大（absmax 3655.81，最小非零 1.0）而绝大多数维度取值极小
  ⇒ 同一 group 的 absmax 把步长撑大 ⇒ **小值维度整片归零**
  ⇒ 39 维状态输入只剩 **16 维有效**（task3）。
- **注意力输入投影**：分布重尾（少数离群大值 + 大量小权重）⇒ 离群值主导步长 ⇒
  **每张量 15~16% 的小权重被清零**，而张量级相对误差只有 **0.56%**
  ⇒ **范数指标完全看不见这种破坏**。

> **这就是"权重保真度不能预测任务性能"的定量解释**：
> 被清零的全是**幅值最小**的权重与统计量，而范数由幅值最大的那部分主导。
> 一个"相对误差 0.44%、看起来几乎无损"的 int8 通道，实际删掉了 8.2% 的参数元素。
>
> ⚠️ **但 3.4.4 的后验消融给出了更强的证据**：同一个 int8 算子**一次性**施加时
> 成功率 **0.817**（几乎无损）；放进**训练闭环**却 **0.000**（全灭）。
> ⇒ 真正的问题不是"量化算子有多狠"，而是
> **「在联邦训练闭环里反复施加量化会发生什么」** ——
> 这是一个**训练动力学**问题，不是**单次变换**问题。
> ⇒ 因此**"某张量坏了"式的归因都不够**：normalizer 单独坏（→0.733）、权重单独坏（→0.000）都成立，
> 但真正决定结局的是**闭环施加**这件事本身。

#### 3.4.3 反事实验证（唯一变量 = normalizer）

| 模型（同一 checkpoint，唯一差别） | task3 成功率 |
|---|---|

| `cf_int4_restore`（**只**把 normalizer 换回未量化版本） | **0.000**（0/0/0） |

⇒ **单独修复 normalizer 不足以救回 int4**。
⚠️ 但**这条不能反推"权重侧清零足以致命"** —— 3.4.4 的后验 int4（清零 8.38%）= **0.467**

**六条数据（后验侧）合起来说明三件事：**

1. **后验 int8 = 0.817 ≥ P3-C 基线 0.667**（+15 pp，但基线 CI ±0.20 ⇒ **落在噪声内**）
   ⇒ **一次 int8_g 量化几乎无损**。同一量化方案放进**训练循环**却是 0.000 ⇒
   伤害不来自"量化算子"，来自"把它放进联邦反馈回路"。
2. **只量化 normalizer = 0.733（清零 16.5%）、只量化 trunk = 0.750（清零 0.46%）**
   ⇒ **没有任何单一张量是元凶**，两个极端子集都无损 ⇒ 旧稿的机制归因
   （「量化把 39 维状态归一化器打成 16 维 ⇒ 归零」）**不成立，已撤回**。
3. **后验 int4 = 0.467**（−20 pp vs 0.667）⇒ **位宽在后验侧确实有影响**

与自步长版 `cf_p3c_int8_all` = 0.817 **无差别** ⇒
**清零率的 17.6 倍差异（8.17% vs 0.46%）本身不是元凶**，后验侧甚至看不出差别。

**这三条已出结果的数据，已经足以推翻 3.4.2 的机制归因：**

1. **后验 int8 = 0.817 ≈ 基线 0.717** ⇒ **一次 int8_g 量化几乎无损**。
   同一量化方案放进**训练循环**却是 0.000 ⇒ 伤害不来自"量化算子"，来自"逐轮施加"。
2. **只量化 normalizer = 0.733（清零 16.5%）** ⇒ **"归一化统计量被打坏"不足以致命**。

3. 加上 `cf_int4_restore`（修 normalizer 仍 0.000）与 `c_int4`（不修也 0.000），
   ⇒ 结论从"某一张量坏了"升级为：
   **「逐轮施加于客户端稀疏权重的量化，会在联邦训练的动力学里持续放大损伤；

> 两者指向同一个方法论结论：**离线可测的权重保真度，与闭环任务效用之间不存在可靠映射。**

#### 3.4.5 🔴 剂量-反应矩阵：后验 vs 闭环（**本节是第 4 章通信侧的核心结论**）

把六个后验变体与三个闭环配置放在一起，得到同一量化算子在两种施加方式下的完整对照：

| 量化方案 | **后验施加**（一次性、离线、不参与训练） | **闭环施加**（逐轮、服务器聚合上行权重） | 差值 |
|---|---|---|---|
| **int8_g**（清零 0.46%，rel 0.005） | **0.817** | **0.000** | **−81.7 pp** |
| **int4_g**（清零 8.38%，rel 0.086） | **0.467** | **0.000** | **−46.7 pp** |
| **bit1**（rel 0.59） | 未测（预期更差） | **0.000** | — |
| 正确对照（P3-C fp32） | 0.667 | 0.667 | — |

**三个结论，全部由上表直接支撑：**

1. **闭环把"可忽略的小误差"放大成"全灭"。**
   后验 int8 只清零 0.46% 的元素、相对误差 0.44%，**成功率反而比基线高 15 pp（噪声内）**；
   同一算子放进训练回路 ⇒ **−100%**。⇒ 误差量级与任务损失之间**不存在单调映射**。
2. **闭环把位宽差异压平了。**
   后验侧 int8（0.817）明显优于 int4（0.467），差 35 pp；
   闭环侧 **两者都是 0.000** ⇒ 决定闭环命运的不是"压得多狠"，而是"**是否在回路里**"。
3. **元凶不是任何一张量、也不是量化步长。**
   只量化 normalizer（0.733）、只量化 trunk（0.750）、换用客户端步长（0.800）—— 三种变体全部无损。

#### 3.4.6 机制陈述（含诚实的边界）

**精确表述**：
> 量化器被插入**联邦学习的反馈回路**（服务器对客户端上行权重做量化后再聚合）。
> 它每轮引入的微小扰动（int8 仅 0.46% 元素清零、相对误差 0.44%）
> **改变了全局模型的优化轨迹**，模型最终收敛到任务退化解；
> 而对最终权重施加**同样的**量化（后验）只产生可忽略的影响。
> ⇒ **联邦量化压缩的安全性不能用后验/离线指标评估，必须在训练闭环中评估。**

⚠️ **两种互斥解释尚未做区分性实验（如实记录，不夸大）**：

| 解释 | 含义 | 支持它的证据 |
|---|---|---|
| (A) 扰动被自举放大 | 每轮的小扰动经后续训练累积放大 | 闭环与后验差 81.7 pp |
| (B) 优化路径被改变 | 扰动让模型收敛到**另一个（退化的）解** | 🔴 `quant_drift.jsonl` 显示 int8 的逐轮偏差 **0.003538 → 0.000205（持续下降、无累积）** ⇒ **权重层面并未累积误差** |

⇒ **`quant_drift` 的"逐轮下降"这一证据倾向 (B)**：
**这说明闭环的崩溃不是"噪声把权重磨坏"，而是"训练过程被扰动后收敛到了坏解"。**
⚠️ 两者都指向同一个方法论结论，但**论文里不能写成"量化误差被逐轮放大"**——
现有证据更支持"优化轨迹改变"。要做严格区分，需要"闭环 vs 无闭环"的训练期成功率曲线对比
（本轮未做，列入局限）。

⇒ **通信压缩的安全性不能用后验/离线指标评估，必须在训练闭环里评估**；
⇒ 权重保真度（MSE / 相对误差 / 清零率）与闭环任务效用之间**不存在可靠映射**。

## 四、隐私侧结果（✅ 已锁定）

### 4.1 三个必须先讲清楚的架构事实（全部实测）

1. **反演目标是 ResNet 特征图，不是像素** —— zarr 的 `image` 形状 (N,1,49,512)，
   取值 [0,15.77]（`stems.*_image.net.0.weight`=(128,512) 佐证）⇒ 目标域 (1,1,49,512)，
   **不能用 sigmoid**（若当像素反演，值域对不上，结论会假）。
2. **语言通路在本配置下不存在** —— `policy.modalities=['image','state']`；
   实测 `loss(有语言) − loss(无语言) = 0.000e+00`（eval 模式、确定性）；
   zarr 的 `language (N,16,768)` 是预计算 T5 嵌入但**不被消费**
   ⇒ 路线图原设的"视觉/语言/动作三通路"在本模型上退化为"视觉/状态/动作"。
3. **上行里没有"模态专属"的共享参数** —— `modalities_tokens` 不参与前向（无梯度），
   上行的共享部分只有 trunk + normalizer。

### 4.2 逐通路敏感度（消融法：把该通路换成另一条轨迹的输入）

| 排序依据 | 视觉 | 状态 | 动作 | 稳健性 |
|---|---|---|---|---|
| 幅度 D_m（3 样本均值） | 5.70 | 3.56 | 1.77 | ❌ **不稳健**（action/state 顺序随样本翻转） |

| 目标 | 指标 | 无噪声 | 结果 |

match loss 收敛到 0.0015 但 rel_l2 恒为 1.31 ⇒ 存在退化解。

### 4.4 DP 预算与 H3：等总预算下的两套分配

**自变量必须是 σ 不是 ε**：trunk 17.1M 参数 ⇒ 噪声范数 = σ·C·√17.1M = σ·4139。
ε∈[1,32]（σ∈[1,9]）全落在噪声地板上，曲线是平的；转折在 σ≈1e-4。
用 `dp.allocate_by_sigma(cfg, σ_ref)` 做等总预算对比（同一 σ_ref ⇒ 两方案总 ε 相同）。

**H3（模态感知预算优于统一预算）在两种口径下都不成立 —— 机制性负结果：**

| 口径 | 定义 | 结果 |
|---|---|---|
| A（max 取全部本地组） | 模态感知把最大 ε 给**不上传的 vision 组** | 外传 shared 只拿 0.5ε_total ⇒ **σ_shared 恒为 uniform 的 1.414×** ⇒ 保真度**每个 σ 点都更低** ⇒ **H3 被推翻** |
| B（max 只在上传组取） | 锚点变成 shared | 模态感知与统一预算**对 trunk 完全等价** ⇒ H3 不成立（无差异） |
| modality_rev | 按实测方向泄漏排序分配 | ε_shared = 0.2ε_total ⇒ **σ_shared = 2.236×σ_ref（更大，不是更小）** ⇒ 保真度 0.7338 < uniform 0.9240 |

> **结构性结论**：等总 ε 下，**任何把预算分给别的组的方案都会削弱对外传 shared 的保护**。
> 这不是实现 bug，而是"并行组合下总 ε = max_m ε_m"这一语义的必然结果。

#### 4.6.3 🔴 代理指标的真实角色：**双向失效**（本轮最重要的方法论结论）

把 4.6 的真实成功率与 4.5 的代理指标逐点对表：

| σ | 真实成功率（真指标） | 代理：共享主干保真度 | 代理：动作 cos | **代理有没有报警？** |
|---|---|---|---|---|
| 1e-4 | **0.000** | 0.924（几乎无损） | 0.971（与无噪声持平） | ❌ **没报警**（保真度 0.924 看起来很健康） |
| 1e-3 | **0.000** | 0.235（明显下降） | 0.974（反而略高于无噪声） | ❌ **没报警**（cos 0.974 > 无噪声 0.971） |
| 1e-2 | **0.000** | 0.024（已崩） | 0.956（几乎无减弱） | ❌ **没报警**（两个代理都没反映效用已死） |
| 1（仅隐私侧） | 未测 | 0.0005（已崩） | 0.934（几乎无减弱） | ✅ 报警，但此时早已无用可保 |

**两个方向的失效**：

1. **低 σ 端：代理指标"过于乐观"，漏报了效用崩塌。**
   σ=1e-4 时共享主干保真度 0.924（几乎无损），**真实成功率却是 0.000**。
   ⇒ 只看代理指标会得出"σ=1e-4 完全安全、可以放心加噪"的结论，**而实际上策略已经全灭**。
   ⇒ 这是"代理保真度替代真实成功率"这一实验设计的**危险方向**：代理指标**高估**了可用性，
   **不是**低估伤害。
2. **高 σ 端：代理指标"过于悲观"，提前报损。**
   σ=1e-2 时保真度已崩到 0.024，但隐私侧动作 cos 仍有 0.956
   ⇒ 此时"效用已经没了，隐私也几乎没变好"，**双输**。
   ⇒ 用代理指标画的"隐私-效用权衡"曲线，在低 σ 端会**系统性高估**这条曲线有多好。

**为什么会出现这种脱节（机制解读）**：保真度这一代理指标测的是
**"共享主干的学习信号是否还能被攻击者看清"**（`fidelity_by_group.shared` 是从反演侧算的），
它天然与**隐私**侧同向，而**不与效用**同向。用它去代理"任务还能不能学会"，
方向上本来就没有保证 —— 本轮数据把这个隐患**实测暴露**出来了。

⇒ **第四章的口径必须改写**：
**代理保真度只能当作"效用崩塌的粗略下界信号"，不能当作"效用还在"的证明；
判断 DP 是否可用，必须同时看真实任务成功率与隐私侧指标，任何一方单独都不成立。**
这与 3.4.4 的方法论结论（**离线可测的权重保真度与闭环任务效用之间不存在可靠映射**）
是**同一个结构性事实的两个实例** —— 本轮把它从"压缩"推广到了"噪声"。

> ⚠️ **一处必须写清的口径差**：代理指标来自**隐私侧**的预算分配实现
> （`dp.allocate_by_sigma`，uniform、按模态分 σ），真实成功率来自**客户端侧统一 σ 加噪器**
> （`dp_noise_client.py`，每坐标 std = σ·C，加噪后原地写回上行）。
> 两者**同 σ、同实验台、同 50 轮、同 C**，但**加噪实现路径不同**。
> ⇒ 因此"代理 0.924 vs 真实 0.000"应读作
> **"在相近噪声水平下，代理指标给出的效用信号与真实任务效用严重脱节"**，
> 而不是"同一份加噪的两个读数互相打架"。
