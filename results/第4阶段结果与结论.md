## 一、一句话结论（隐私侧已锁定，通信侧待补）

FedVLA 的上行更新（trunk + normalizer + modalities_tokens）**泄漏的是客户端的私有动作序列**，
而不是视觉观测：攻击者能从 17.1M 维的共享主干梯度里把 8×4 的动作块**近乎完整地还原**
（余弦 0.97，rel_l2 0.24），却**完全无法还原视觉特征**（逐 patch 相关 0.03）。
更糟的是，**客户端级 DP 在这个模型规模上无法同时满足效用与隐私**：
噪声小到还能学习时（σ=1e-4）攻击几乎不受影响（cos 0.971 vs 无噪声 0.972）；
噪声大到开始伤害攻击时（σ=1e-2），共享主干的学习信号保真度已跌到 **0.024**——训练本身先废了。

**H3 的最终判定：被推翻，且对 DP 组合口径不敏感。** 三套等总 ε 的预算分配
（uniform / 先验模态感知 / 按实测可攻击性重分配 modality_rev）在动作泄漏强度上
**几乎无差别**（σ=1 时三者动作 cos 全是 0.934），但共享主干保真度上
**modal_rev < modality < uniform 在全部 5 个 σ 点严格成立**
（σ=1e-4：0.734 < 0.863 < 0.924）⇒ **按模态分预算在"上行联邦 + 并行组合 DP"下
结构性地损害真正外传的通道**，而不是改善它。

**方法论上的自我补强（4.6）**：上述"保真度"是**代理指标**，不是任务成功率。
为避免整章建立在一个未经检验的代理上，现补做**同一 σ 上的真实任务成功率曲线**
（真实 MuJoCo 评估，3 seeds × 20 rollouts），与代理指标逐点对表 ——
这使第四章从"只有代理指标"升级为"代理指标 + 真实指标 + 两者可比"。

### 2.3 DP 效用实验配置（真实任务成功率 ↔ 代理指标交叉验证）

> **为什么必须做**：第四节的隐私侧原本只有**代理指标**（共享主干学习信号保真度）。
> 论文只报代理指标，委员会一定会问"那真实任务还能不能学会？"
> ⇒ 必须补一条**真实任务成功率**随 σ 的曲线，与代理指标在**同一个 σ** 上对表。

| 项 | 取值 | 理由 |
|---|---|---|
| 实验台 | 与通信扫描**完全一致**的 P3-C（异构 + MoE + 簇感知，50 轮） | 唯一变量 = 上行 DP 噪声 σ ⇒ 干净基线可直接复用 `c_drop00` |
| 加噪位置 | **客户端上行前**（改写客户端 `model.pth` 的共享参数） | 威胁模型是"服务器观察上行"。加噪做在客户端侧 ⇒ **完全不需要改 `aggregate.py`**（它正被通信扫描占用） |
| 加噪形式 | `Δ·min(1, C/‖Δ‖₂) + N(0,(σC)²)`（**per-coordinate**） | DP-FedAvg 标准形式；上行 = 非 `stems.*`/`heads.*` 的全部键（个性化参数不上行，不加噪） |
| C 标定 | C = ‖Δ‖₂ **中位数**（跑 2 轮干净训练实测） | ε 只依赖 σ（ε ∝ 1/σ²），C 是纯效用旋钮；取中位数让裁剪真正生效 |
| σ 网格 | **1e-4 / 1e-3 / 1e-2** | 与隐私侧 uniform 方案**完全一致** ⇒ 真实指标与代理指标可在同一 σ 上对表 |
| 噪声/信号比 | **σ·√d**（d≈17.1M ⇒ √d≈4134） | σ=1e-4 → 0.41（与信号同量级）；1e-3 → 4.1；1e-2 → 41 |
| ε 口径 | δ=1e-5，q=1/4（4 客户端），steps=50 | 与隐私侧同一个 RDP accountant ⇒ ε 直接可比 |
| 评估 | task3，3 seeds × 20 rollouts | 与通信侧同口径 |

> 🔴 **一个曾经栽进去的坑（已由离线单元测试抓出）**：DP 噪声是**逐坐标**的，
> 所以总噪声范数 = σ·C·√d，而信号范数 = C ⇒ **噪声/信号比 = σ·√d**，
> **不是** σ。初版设计误以为 σ 就是噪声/信号比，据此把网格定成 {0.01, 0.1, 1.0}，
> 实际噪声是信号的 41~4134 倍 ⇒ 整个网格选错量级。
> 修正后与隐私侧网格对齐（见 `federated/test_dp_noise_client.py`，本地+云端各跑一遍，5 项全通过）。
> **教训：新写的实验代码先离线单测**——5 分钟的单测省下 6 小时算力。

## 四、隐私侧结果（✅ 已锁定）

### 4.1 三个必须先讲清楚的架构事实（全部实测）

1. **反演目标是 ResNet 特征图，不是像素** —— zarr 的 `image` 形状 (N,1,49,512)，
   取值 [0,15.77]（`stems.*_image.net.0.weight`=(128,512) 佐证）⇒ 目标域 (1,1,49,512)，
   **不能用 sigmoid**（若当像素反演，值域对不上，结论会假）。
2. **语言通路在本配置下不存在** —— `policy.modalities=['image','state']`；
   实测 `loss(有语言) − loss(无语言) = 0.000e+00`（eval 模式、确定性）；
   zarr 的 `language (N,16,768)` 是预计算 T5 嵌入但**不被消费**
   ⇒ 路线图原设的"视觉/语言/动作三通路"在本模型上退化为"视觉/状态/动作"。
3. **上行里没有"模态专属"的共享参数** —— `modalities_tokens` 不参与前向（无梯度），
   上行的共享部分只有 trunk + normalizer。

### 4.2 逐通路敏感度（消融法：把该通路换成另一条轨迹的输入）

| 排序依据 | 视觉 | 状态 | 动作 | 稳健性 |
|---|---|---|---|---|
| 幅度 D_m（3 样本均值） | 5.70 | 3.56 | 1.77 | ❌ **不稳健**（action/state 顺序随样本翻转） |
| **方向泄漏强度 1−cos** | 0.760 | 0.136 | **1.358** | ✅ **三样本一致** |

⇒ **幅度敏感度不能单独用于排序**；本阶段统一采用"方向泄漏强度 1−cos"作为排序依据。
⇒ donor 必须**跨 episode**（相邻索引是同轨迹相邻时间步，动作几乎相同，会给出虚假的高泄漏）。

### 4.3 梯度反演攻击：什么能被还原，什么不能

| 目标 | 指标 | 无噪声 | 结果 |
|---|---|---|---|
| 动作（标签） | 余弦相似度 | **0.972** | **0.972**（rel_l2 0.244）✅ 近乎完整还原 |
| 视觉（输入） | 逐 patch Pearson | 0.001 | **0.026** ❌ 完全失败 |
| 状态（输入） | 余弦相似度 | 0.000 | **0.301** ❌ 失败（量级远低于动作） |

⇒ 上行梯度泄漏的是**标签**，不是观测。
⇒ 视觉/状态反演失败的原因是 17.1M 维主干的**维度诅咒**，
已用对照组排除"优化不足"：300/600 步 × lr 0.05/0.01 × dense/all 匹配集下，
match loss 收敛到 0.0015 但 rel_l2 恒为 1.31 ⇒ 存在退化解。

### 4.4 DP 预算与 H3：等总预算下的两套分配

**自变量必须是 σ 不是 ε**：trunk 17.1M 参数 ⇒ 噪声范数 = σ·C·√17.1M = σ·4139。
ε∈[1,32]（σ∈[1,9]）全落在噪声地板上，曲线是平的；转折在 σ≈1e-4。
用 `dp.allocate_by_sigma(cfg, σ_ref)` 做等总预算对比（同一 σ_ref ⇒ 两方案总 ε 相同）。

**H3（模态感知预算优于统一预算）在两种口径下都不成立 —— 机制性负结果：**

| 口径 | 定义 | 结果 |
|---|---|---|
| A（max 取全部本地组） | 模态感知把最大 ε 给**不上传的 vision 组** | 外传 shared 只拿 0.5ε_total ⇒ **σ_shared 恒为 uniform 的 1.414×** ⇒ 保真度**每个 σ 点都更低** ⇒ **H3 被推翻** |
| B（max 只在上传组取） | 锚点变成 shared | 模态感知与统一预算**对 trunk 完全等价** ⇒ H3 不成立（无差异） |
| modality_rev | 按实测方向泄漏排序分配 | ε_shared = 0.2ε_total ⇒ **σ_shared = 2.236×σ_ref（更大，不是更小）** ⇒ 保真度 0.7338 < uniform 0.9240 |

> **结构性结论**：等总 ε 下，**任何把预算分给别的组的方案都会削弱对外传 shared 的保护**。
> 这不是实现 bug，而是"并行组合下总 ε = max_m ε_m"这一语义的必然结果。

### 4.5 隐私-效用权衡（本阶段最重要的表）

三套预算方案**总 ε 完全相同**（同一 σ_ref ⇒ 同一 ε_total），可直接横向比：

| σ | 总 ε | 动作重建 cos<br>unif / modal / **modal_rev** | 状态 cos<br>(unif) | 视觉 corr<br>(unif) | 共享主干保真度<br>unif / modal / **modal_rev** |
|---|---|---|---|---|---|
| clean | — | 0.971 / 0.972 / 0.974 | 0.301 | 0.026 | — |
| 1e-4 | 5e+09 | 0.971 / 0.972 / 0.974 | 0.331 | 0.024 | **0.924** / 0.863 / 0.734 |
| 1e-3 | 5e+07 | 0.974 / 0.975 / 0.973 | 0.254 | 0.026 | **0.235** / 0.169 / 0.108 |
| 1e-2 | 4.999e+05 | 0.956 / 0.946 / 0.943 | **0.444** | 0.024 | **0.024** / 0.017 / 0.011 |
| 0.1 | 4873 | 0.938 / 0.937 / 0.936 | 0.079 | 0.009 | **0.0026** / 0.0019 / 0.0013 |
| 1 | 16.55 | 0.934 / 0.934 / 0.934 | −0.014 | 0.002 | **0.0005** / 0.0004 / 0.0003 |

三个互锁的结论：
1. **DP 噪声对"标签型泄漏"几乎无效** —— σ 放大 1e4 倍（ε=16.55），动作 cos 仅 0.971→0.934（降 3.8%）。
2. **共享主干的学习信号先崩** —— 保真度 0.924→0.0005 ⇒ **「效用尽毁、隐私不保」**。
3. **状态泄漏非单调虚高** —— σ=1e-2 时 state cos 0.444 > clean 的 0.301，
   这是**噪声主导梯度方向后的伪相关**，不是泄漏变强（必须诚实说明，否则会被误读为"加噪反而更安全"）。
4. **预算分配方案只在"效用"维度上有差别，而且方向为负** —— 动作 cos 三方案差异 < 0.014（≈噪声级），
   保真度却差 1.7 倍 ⇒ 分配得越"精细"，真正外传的 shared 越差。

### 4.6 DP 噪声 vs 真实任务成功率（⏳ 待补：云端接力链排队中）

> **目的**：验证 4.5 的**代理指标**（共享主干学习信号保真度）能否代表**真实任务效用**。
> 两条曲线在**同一个 σ** 上对比 —— 这是本章内部的一次交叉验证，
> 也是回应"你只报了代理指标"这个必然会被问到的问题。
>
> 实验台与通信扫描完全一致（异构 + MoE + 簇感知，50 轮），唯一变量是上行 DP 噪声 σ；
> 干净基线复用通信扫描的 `c_drop00`（同一实验台、同一轮数、同一 MoE 配置）。

| σ | 噪声/信号比<br>(=σ·√d) | 总 ε | **真实成功率**<br>(均值 ± 95% CI) | 代理：共享主干<br>保真度 | 代理：动作<br>重建 cos |
|---|---|---|---|---|---|
| 0（无 DP） | 0 | ∞ | 待填（＝`c_drop00` 基线） | 1.000 | 0.972 |
| 1e-4 | 0.41 | 5.0e+09 | 待填 | 0.924 | 0.971 |
| 1e-3 | 4.1 | 5.0e+07 | 待填 | 0.235 | 0.974 |
| 1e-2 | 41 | 4.999e+05 | 待填 | 0.024 | 0.956 |

> 代理指标两列直接取自 4.5 的 uniform 方案实测值（已锁定），无需重算。

**判定标准先写在这里（避免事后编故事）**：

| 若出现 | 则结论是 |
|---|---|
| 真实成功率随 σ **单调下降**，且转折点与代理保真度一致 | 代理指标是**可靠的代理** ⇒ 本章"用保真度替代成功率"的实验设计成立 |
| 代理保真度已崩，但真实成功率**仍明显高于 0** | 代理指标**高估**了伤害（保守方向）⇒ 必须诚实写出"代理指标是悲观上界" |
| σ=1e-4 就已归零 | 本任务对上行噪声**极其敏感**，⇒ "DP 可用窗口"在本实验台上不存在 |
| 真实成功率在某个 σ 上**反而升高** | 说明噪声起了正则化作用 ⇒ 需做多 seed 复现，排除 seed 方差 |

**若曲线单调且与代理同形**，则本章可给出一个更强的命题：
*上行 DP 的真实代价不是"隐私换不来效用"，而是**在效用崩塌之前，隐私就已经保不住了**——
因为动作标签的泄漏几乎不随 σ 变化（0.971→0.934），而学习信号在 σ=1e-3 就已掉到 0.235。*

## 五、两侧合起来的论文叙事

1. **通信侧**：把 FedVLA 放在受损链路上，看"我们的方法"还剩多少（第三节，待补数据）。
2. **隐私侧**：即便不看攻击者，**上行更新本身就泄漏动作标签**；
   而客户端级 DP 在 22M 参数规模上**无法同时满足效用与隐私**（第四节）。
3. **耦合点**：这两条曲线共用同一个 σ/压缩轴 ——
   上行量化（int8/int4/bit1）省的是**字节数**，
   DP 加噪花的是**隐私预算**；两者都在"上行载荷"这一个维度上做权衡。
   ⇒ 论文可以给出统一的"上行载荷 vs 任务效用 vs 隐私强度"三维图（后续补充）。
4. **内部交叉验证（4.6）**：隐私侧用**代理指标**（保真度）扫 σ，本节用**真实成功率**扫同一个 σ，
   两者在同一个实验台上 ⇒ 可以直接检验"代理指标能不能替代成功率"。
   这一条把第 4 章从"只有代理指标"升级为"代理指标 + 真实指标 + 两者对表"。

   本章原本用"共享主干学习信号保真度"代替任务成功率（因为它无需跑 MuJoCo 评估即可大规模扫描），
   但这确实是本章最需要补强的地方。现已补上 **4.6「DP 噪声 vs 真实任务成功率」**：
   同一实验台、同一 σ 网格、真实 MuJoCo 评估（3 seeds × 20 rollouts），
   与代理指标**逐点对表** ⇒ 代理指标的可靠性可被直接检验，而不是靠论证。
   （残留局限：4.6 只覆盖 **σ∈{1e-4,1e-3,1e-2}** 三个点，
   σ>1e-2 未做真实训练评估 —— 但那已是地板区（保真度 0.024），价值有限。）

2. **反演攻击只覆盖 DLG**。没有对比 GradInversion / iDLG 等更强攻击者，
   所以"动作被完整还原"是**下界**（真实泄漏可能更严重）。
3. **样本量**：隐私侧用 3 个样本 × 200 步 DLG，没有做多 seed 显著性检验
   （通信侧是 3 seeds × 20 rollouts）。趋势方向清晰，但绝对值需谨慎解读。
4. **语言通路缺席**（见 4.1-2），三通路而非路线图原设的四通路。
5. **DP 施加在"客户端本地全部参数"上**，服务器观察其 trunk 子集；
   若只对上行的共享部分加噪，则上行里只剩一个模态组，"模态感知"在 FedVLA 上是空的。
6. **通信侧的 25 轮旧数据已作废**并留档为 `*.r25` / `*.legacy`，
   它是"通信损伤 vs 训练轮数"的对照记录，也是本次 silent failure 的实证。
7. **σ 与 ε 不是线性反比（差点栽在这里）**。固定 (δ, steps) 时 RDP accountant 给出
   **ε ∝ 1/σ²**（σ ∝ 1/√ε）。手稿曾按"ε_shared 缩小 5 倍 ⇒ σ_shared 缩小 5 倍"
   推演出 0.447 σ_ref，**符号写反**；实测是 **2.236 σ_ref = √5**（与 √5 精确吻合）。
   ⇒ 跨预算方案的定量对比必须读实测的 σ 分配表（`privacy_budget_table.md`），
   不能靠 ε 的比例手推 σ。
8. **隐私侧补跑曾因漏 `--dp-steps 50` 失效**（argparse 默认 25 ⇒ 总 ε 减半 ⇒ 不可比），
   已用 `purge_privacy_mode.py` 清除 19 条错误记录后按完整参数重跑；
   现云端 `privacy_results.json` 共 154 条记录，meta.dp_steps=50，**三方案总 ε 严格相等**。

## 八、复现命令

```bash
# 云端（AutoDL）：第4阶段一键续跑（幂等，每步可单独重跑）
bash /root/fedcore/resume_phase4.sh all

# 分步
bash /root/fedcore/resume_phase4.sh clean     # 清洗遗留权重
bash /root/fedcore/resume_phase4.sh privacy   # 隐私侧 modality_rev 补跑
bash /root/fedcore/resume_phase4.sh comm      # 通信扫描 v2（50 轮 × 7 配置）
bash /root/fedcore/resume_phase4.sh extract   # 提取两侧结果（含基线自检）

# DP 效用扫描（真实成功率 vs 代理指标）
bash /root/fedcore/chain_phase4_dp.sh          # 串行接力：等通信扫描 → 标定 → 扫描 → 提取
# 或分步
bash /root/fedcore/calibrate_dp_clip.sh        # C 标定（2 轮干净训练）
bash /root/fedcore/run_dp_utility.sh           # σ 扫描（3 配置 × 50 轮 × 3 路并行）
/root/miniconda3/envs/hpt/bin/python /root/fedcore/extract_dp_utility.py

# 加噪器离线单测（无需 GPU，本地/云端各跑一遍）
python /root/fedcore/test_dp_noise_client.py

# 出表 + 出图
python /root/fedcore/extract_comm_results.py
python /root/fedcore/extract_privacy_results.py \
    --json /root/HPT/output/privacy/privacy_results.json \
    --out  /root/HPT/output/privacy
```

> ⚠️ **不要原地改正在被执行的 bash 脚本**（bash 逐行读文件 → 读到错乱字节）。
> 正确做法：写 `.new` + `mv` 原子替换（rename 不改 inode ⇒ 运行中的进程继续读旧 inode，实测安全）。
> `run_fedavg.sh` 的 `POST_CLIENT_HOOK` 钩子就是用这个方式加进去的（默认空 ⇒ 行为逐字节不变）。
