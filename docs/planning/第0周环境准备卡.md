# 第 0 周：环境准备卡（WSL2 + Ubuntu）

## 0. 先回答问题：全程在 Ubuntu 里吗？

**实验相关的一切在 Ubuntu，论文写作在 Windows。** 但"Ubuntu"指的是 **WSL2 里的 Ubuntu**，不是双系统、不是单独一台机器。

原因只有一个，但很硬：HPT 仓库钉着 `mujoco-py`（MuJoCo 2.1 的 Python 绑定，需要本地编译，**没有 Windows 版本**），Meta-World 官方也声明只测试 Linux/macOS。这两个是你的仿真底座，绕不开。

**不要装双系统。** 你 6 个月里有大量时间在写论文、画图、读文献、整理表格，这些在 Windows 上顺手得多（尤其是学校给的是 Word 模板）。双系统每次切换要重启，会把你的工作切成两半。

## 1.1 如果你现在用的是 VMware：确实不对，但只错在一个点

**VMware Workstation 不支持把物理 GPU 暴露给虚拟机里的 CUDA。** 这不是配置问题，是架构限制——它没有 PCIe 设备直通（那是 ESXi / KVM 的功能），它的"3D 加速"只是把 OpenGL / DirectX 调用转回宿主机渲染，虚拟机里看到的是一块虚拟显卡。

判据很简单，你现在就可以在 VMware 的 Ubuntu 里试：

```bash
nvidia-smi
```

报 `command not found` 或看不到你的物理显卡，就确认了。

**后果**：`torch.cuda.is_available()` 会是 `False`，HPT 的训练脚本大概率直接报错——它假设有 GPU。也就是说 VMware 里的 Ubuntu 能装包、能写代码、能跑 numpy 的部分，但**跑不了任何真正的训练实验**。

### 三条出路，按推荐顺序

| 路线 | GPU | 迁移成本 | 切换成本 | 适合 |
|---|---|---|---|---|
| **WSL2（推荐）** | 可用，NVIDIA 官方支持 | 1–2 小时重装 | 零，和 Windows 并排窗口 | 你的首选 |
| 双系统 | 完全可用 | 半天 | 每次重启 1–2 分钟 | 只在 WSL2 反复失败时 |
| 云 GPU（AutoDL 等） | 完全可用，且能租 4090 24GB | 半天 | 零，SSH 连上去 | 本地装不上、或想跑更大实验时 |

**为什么首选 WSL2**：CUDA on WSL 是 Microsoft 和 NVIDIA 联合支持的官方路径，不是 hack；零额外成本；和 Windows 文件互通，写论文、拷图都方便；你的模型只有 12.6M，8GB 显存本来就够，不需要更强的卡。

**为什么云 GPU 反而是很好的 B 计划**：HPT-Base 12.6M、3 个任务、50 轮 × 3 epoch，主实验 12 个配置 × 3 seeds，粗估总共 50–100 GPU 小时，按 AutoDL 4090 约 1.5 元/小时算，**一百多块钱能跑完整个论文的实验**。而且 24GB 显存意味着你能跑更多 seeds、更多任务、更大的 batch——比你本地 8GB 卡更宽裕。唯一的代价是环境要在云上再装一遍。

### 关于 VMware 里已经装好的东西

**经验全部可复用，环境不要迁移。** 你踩过的坑、学会的命令、对依赖关系的理解都带得走，但虚拟机的磁盘镜像搬到 WSL2 既慢又容易留下隐蔽的路径依赖。**重装一遍更快也更干净**——第二次装通常比第一次快一半以上，因为你已经知道坑在哪。

VMware 里的 Ubuntu 可以留着当**代码沙盒**：写 `federated/`、`comms/`、`privacy/` 这些纯 Python 的部分、跑 numpy 单元测试，都是 CPU 就能做的。但**在它身上最多再花 2 小时**，不要把排期押在上面。

### 1.1.1 如果决定用云服务器

**那就 VMware 和 WSL2 都不用装了**，本地 Windows 只需要能开浏览器、VS Code 和 SSH。

云路线和 WSL2 的关键差别：云上是**原生 Linux**，没有 `/mnt/c/` 跨文件系统那个坑，编译 `mujoco-py` 更顺；而且显卡从 8GB 变成 24GB，可以把 seeds 从 3 加到 5、batch 和任务数也放宽——**统计充分性这条硬门槛能做得更扎实**。

完整的选型、无卡模式省钱、连接方式、持久化策略和 24GB 显存的配置调整，见 **`云服务器方案.md`**。环境安装已经固化成 `setup_cloud.sh`（工作区根目录），无卡模式下一键跑完。



在 Windows 的 **PowerShell（管理员）** 里：

```powershell
wsl --install -d Ubuntu-22.04
```

装完重启，设置好用户名密码。然后确认一件事：

```powershell
wsl -l -v        # 应该看到 Ubuntu-22.04  Running  VERSION 2
```

**如果是 VERSION 1，先升级**：`wsl --set-version Ubuntu-22.04 2`。

### 2.1 限制 WSL2 的资源占用（不设会拖慢 Windows）

在 **Windows 侧**创建 `C:\Users\hp\.wslconfig`：

```ini
[wsl2]
memory=10GB
processors=6
swap=8GB
```

`memory` 按主机物理内存的 **60%** 给：主机 16GB → 10GB；32GB → 16GB；只有 8GB → 给 5GB，并且要意识到 Meta-World 的数据加载吃内存，可能要把 `dataset.episode_cnt` 压到 50。

改完在 PowerShell 里 `wsl --shutdown` 再重开才生效。

## 3. 文件系统规则（最容易毁掉体验的一条）

**代码、数据集、checkpoint 全部放在 WSL2 自己的 ext4 里，例如 `~/projects/fedvla/`。**

**绝对不要放在 `/mnt/c/Users/...`。** WSL2 访问 Windows 文件是跨文件系统的网络 IO，编译 `mujoco-py` 和遍历数据集会慢一个数量级，你会以为环境有问题。

反过来，从 Windows 访问 WSL2 里的文件是允许的（`\\wsl.localhost\Ubuntu-22.04\home\...`），但只用来拷贝结果，不要在 Windows 侧直接编辑 Linux 里的代码。

**跨边界只走两样东西**：论文文档、最终的图片和表格。其余都在里面。

## 4. GPU 直通验证（先做，别急着装包）

在 WSL2 终端里：

```bash
nvidia-smi
```

**能看见你的显卡，就成功了一大半。** 看不到的话：

1. Windows 侧的 NVIDIA 驱动太老 → 去官网更新到最新（不需要特定版本，越新越好）
2. **不要在 WSL2 里装 Linux 版 NVIDIA 驱动** —— 这是最常见的自毁操作，会和宿主机驱动冲突
3. 确认 Windows 版本 ≥ Win10 21H2 或 Win11

## 5. 系统依赖（apt）

```bash
sudo apt update && sudo apt install -y \
  build-essential \
  libgl1-mesa-dev libgl1-mesa-glx libglew-dev \
  libegl1-mesa libegl1-mesa-dev libosmesa6-dev \
  libxrender1 libxext6 libsm6 \
  patchelf wget curl git unzip
```

`patchelf` 是 `mujoco-py` 用来打二进制补丁的，缺了会报莫名其妙的错；EGL / OSMesa 是离屏渲染用的，缺了渲染会失败。

## 6. MuJoCo 210

```bash
mkdir -p ~/.mujoco && cd ~/.mujoco
wget https://mujoco.org/download/mujoco210-linux-x86_64.tar.gz -O mujoco210.tar.gz --no-check-certificate
tar -xvzf mujoco210.tar.gz

cat >> ~/.bashrc <<'EOF'
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$HOME/.mujoco/mujoco210/bin
export MUJOCO_GL=egl
export WANDB_MODE=offline
export HF_ENDPOINT=https://hf-mirror.com
EOF
source ~/.bashrc
```

`HF_ENDPOINT` 那行是给国内网络用的镜像，下载 HPT 预训练权重会快很多，别省。

## 7. conda 环境与 PyTorch

```bash
conda create -n hpt python=3.10 -y && conda activate hpt

# 用 cu118 的 wheel，自带 CUDA 运行时，不用在系统里装 CUDA Toolkit
pip install torch==2.1.1 torchvision==0.16.1 --index-url https://download.pytorch.org/whl/cu118
```

**Python 必须是 3.10**：HPT 钉了 `numpy==1.24.3`，3.11 以上会有编译问题。

然后装 HPT 的子集依赖（**不要直接 `pip install -e .`**，会拉 tensorflow 全家桶）：

```bash
git clone https://github.com/liruiw/HPT.git && cd HPT
pip install -e . --no-deps
pip install "numpy==1.24.3" "gym==0.26.2" "gymnasium>=0.29.0" \
  "mujoco-py" "Cython==0.29.36" "scipy==1.10.1" "imageio==2.27.0" \
  "hydra-core==1.3.2" "hydra-joblib-launcher" "einops==0.7.0" "timm==0.9.12" \
  "transformers==4.36.0" "scikit-learn==1.3.2" "matplotlib==3.7.4" \
  "seaborn==0.13.0" "opencv-python==4.8.1.78" "tqdm==4.66.1" "tabulate==0.9.0" \
  "easydict==1.11" "transforms3d==0.4.1" "wandb==0.16.1" "lxml==4.9.3" \
  "GPUtil==1.4.0" "pyvirtualdisplay==3.0" "protobuf==3.20.3"
```

Meta-World **不用装**——HPT 仓库里内置了一份完整副本，在 `env/mujoco/metaworld/`（有 `LICENSE`、`envs/`、`policies/`、`test_scripted_policies.py`）。`rollout_runner.py` 用的是相对导入 `from .envs.mujoco.sawyer_xyz.test_scripted_policies import ALL_ENVS`，所以它在 HPT 自己的包空间里运行，不依赖 PyPI 上的 `metaworld`。

这也解释了为什么 HPT 的依赖清单里压根没写 Meta-World——**它自带**。

**所以：绝对不要 `pip install metaworld`。** PyPI 上的最新版是 3.x，用 gymnasium API 和 MuJoCo 3，装上了只会和内置版本冲突。

环境名确认是 `-v2` 系列：`reach-v2`、`push-v2`、`button-press-topdown-v2`、`door-open-v2`。用的是老 gym API（`env.step()` 返回 4 元组而不是 5 元组），这就是为什么依赖里同时钉了 `gym==0.26.2` 和 `gymnasium>=0.29.0`——两个都要。

验证（在 HPT 目录下执行，应输出 50）：

```bash
python -c "from env.mujoco.metaworld.rollout_runner import ALL_TASK_CONFIG; print(len(ALL_TASK_CONFIG))"
```

能输出 50 就说明内置环境代码可导入，这一步没有别的坑了。

## 8. VS Code 怎么接

1. Windows 上装 VS Code + 扩展 **Remote - WSL**
2. 在 WSL2 终端里 `cd ~/projects/fedvla && code .`
3. 之后终端、调试、Python 解释器全在 Linux 侧，界面还是 Windows 的

## 10. 常见坑与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `nvidia-smi` 找不到命令 | 驱动或 WSL 版本问题 | 更新 Windows 侧 NVIDIA 驱动；**不要装 Linux 驱动** |
| `mujoco-py` 编译时报 `patchelf` 缺失 | 系统依赖没装全 | `sudo apt install patchelf` |
| 渲染黑屏 / `Failed to initialize GLFW` | 无显示，EGL 失败 | 改 `export MUJOCO_GL=osmesa`，或换 `egl` 二选一都试一遍 |
| `ImportError: numpy/arrayobject.h` | Cython 编译时找不到 numpy 头 | 确认 `Cython==0.29.36` 与 `numpy==1.24.3` 同时装上 |
| 下载 HPT 权重超时 | 网络 | `export HF_ENDPOINT=https://hf-mirror.com` |
| 编译/读数据极慢 | 仓库放在 `/mnt/c/` | 移到 `~/projects/` |
| Windows 侧很卡 | WSL2 吃太多内存 | 调 `.wslconfig` 的 `memory` |
| `torch` CUDA 不可用 | 装了 CPU 版 wheel | 重装，务必带 `--index-url .../cu118` |
