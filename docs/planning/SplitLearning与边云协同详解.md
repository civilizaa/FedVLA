# Split Learning 与边云协同：两个方向的细节

> 面向：通信硕士（放养）、委员会以通信为主、纯仿真、8GB 显存、Windows、目标转机器人就业。

---

# 第 0 部分：Split Learning 概念速查

## 0.1 一句话

**把神经网络按层切成两段，客户端只跑前段、只上传中间结果，服务器跑后段并把梯度传回来。** 原始数据不出端，完整模型也不在任何一端。

## 0.2 它为什么存在（联邦学习的两个硬约束）

| 联邦学习的约束                     | Split Learning 的解决方式 |
| --------------------------- | -------------------- |
| 客户端必须跑得动**完整模型**的前向与反向      | 客户端只跑前几层，算力与显存要求大幅下降 |
| 所有客户端模型**结构必须一致**（否则参数没法平均） | 只需前段一致，后段可不同，天然支持异构  |
| 需要把**模型权重**交给服务器聚合          | 权重不上行，服务器也拿不到完整模型    |

一句话概括：**联邦学习降低的是"数据集中"的需求，split learning 降低的是"客户端能跑完整模型"的需求。**

## 0.3 与联邦学习的结构对比

|         | 联邦学习          | Split Learning |
| ------- | ------------- | -------------- |
| 客户端持有   | 完整模型副本        | 只有前几层          |
| 本地做     | 完整前向 + 反向     | 前向到切分层为止       |
| 上传      | 模型权重或梯度（每轮一次） | 中间激活（每个 batch） |
| 服务器做    | 只做加权平均        | 跑后几层 + 算损失     |
| 回传      | 新的全局模型        | 切分层处的梯度        |
| 通信量     | 小（一轮一次）       | **大**（每步都传）    |
| 客户端算力要求 | 高             | 低              |
| 模型结构要求  | 必须一致          | 只需前段一致         |

**一个比方**：联邦学习是每人拿一本完整教材自学，定期交笔记给老师合并；split learning 是教材撕成两半，学生只有前半本，做到一半把草稿纸交给老师，老师用后半本算完答案再把批改发回来。

## 0.4 三种变体

| 变体           | 流程                           | 特点                  |
| ------------ | ---------------------------- | ------------------- |
| Vanilla      | C1 → S → C2 → S → C3         | 客户端轮流占用服务器，串行，人多时很慢 |
| **SplitFed** | C1/C2/C3 并行 → S（再做一次 FedAvg） | 并行快，且能和联邦基线公平对比     |
| U 型分割        | C 前段 → S → C 后段              | 连标签都不上传，隐私最强，实现最麻烦  |

## 0.5 优缺点

**优点**

- 客户端算力与显存压力小，弱设备也能参与大模型训练
- 原始数据与标签都不出端
- 模型权重不共享，服务器拿不到完整模型，客户端也拿不到
- 支持客户端之间的模型结构异构

**缺点**

- **通信量远大于联邦学习**（每个 batch 都要传激活和梯度）
- 训练过程有顺序依赖，vanilla 变体下并行度差
- 两端学习率与更新节奏不同步，训练稳定性比联邦学习差
- 上传的激活可被特征反演攻击，浅层切分几乎能重建原始输入

## 0.6 什么时候该用它

用：**客户端设备算力弱、模型太大跑不动、或不想把模型结构交出去**的场景。

不用：客户端本来就能跑完整模型、且带宽紧张的场景——此时联邦学习更省通信。

对你的具体场景：机器人终端算力受限是真实的工业约束（这也是为什么 split learning 在具身智能里值得一做），但**在单机串行仿真里显存优势体现不出来**，要如实说明。

## 0.7 迁移学习、联邦学习、Split Learning 的异同（与第 0.6 节配套）

### 0.7.1 一句话定位：它们不在同一个维度上

- **迁移学习**回答的是：**一份已有的知识，怎么用到新任务上**（单方视角，纵向问题）。
- **联邦学习 / Split Learning** 回答的是：**多个参与方，怎么在不交换数据的前提下共同训练**（多方视角，横向问题）。

所以它们**不是竞争关系，而是正交关系**，可以叠加。这也是本节最重要的结论。

### 0.7.2 六维对照

| 维度       | 迁移学习                 | 联邦学习                     | Split Learning           |
| -------- | -------------------- | ------------------------ | ------------------------ |
| 首要动机     | 目标域数据/算力不够，借用源域      | 数据孤岛 + 隐私，不能集中           | 客户端**跑不动完整模型** + 隐私      |
| 原始数据     | 通常集中可用               | 不出本地                     | 不出本地，标签也可不出              |
| 各方持有     | 一方持有完整模型（或其副本）       | 每方一份**完整模型副本**           | 每方只持有**一段**，没有完整模型        |
| 时序       | **串行**：先训源任务，再迁到目标任务 | **并行**：本地多步训练，周期性与服务器往返  | **协同**：逐 batch 往返，强顺序依赖   |
| 通信是不是瓶颈  | 通常不是                 | 是                        | **更是**（每步都传激活与梯度）         |
| 典型关键词    | 负迁移、域差距、微调、冻结层       | 非独立同分布、客户端漂移、聚合、通信轮次     | 切分点、激活压缩、特征反演、staleness  |

一句话判据：**通信是不是瓶颈，是区分三者最实用的一条。** 只有后两者需要你认真建模链路，也只有它们的优化问题天然属于通信学科。

### 0.7.3 各自的典型失效模式（写论文时要用它来设计对照实验）

| 范式            | 失效模式                                | 观察指标                      | 常用缓解                     |
| ------------- | ----------------------------------- | ------------------------- | ------------------------ |
| 迁移学习          | **负迁移**：迁移后比从零训还差                   | 目标任务成功率低于 no-pretrain 基线  | 冻结部分层、更小的学习率、先做域适配       |
| 联邦学习          | **客户端漂移**：非独立同分布下各客户端越训越远，聚合后反而变差   | 各客户端本地损失发散，全局准确率震荡甚至低于单客户端 | FedProx 近端项、个性化层、减少本地步数  |
| Split Learning | **训练不稳定 + 特征反演泄露**                  | 损失抖动、激活大小爆炸；浅层切分可被重建输入    | 两端学习率解耦、梯度裁剪、深一点切分 + 噪声/量化 |

注意：这三列正好对应你论文**消融实验**的三类变量。答辩时把"我们观察到了 X 失效现象，并用 Y 机制缓解"讲清楚，比罗列一堆机制更有说服力。

### 0.7.4 叠加是可以的，而且大家都在叠加

| 组合                  | 实例                                       | 备注                        |
| ------------------- | ---------------------------------------- | ------------------------- |
| 迁移 ⊕ 联邦             | **你现在准备做的**：HPT 预训练权重起步，多客户端联邦微调        | 预训练解决"从零训不动"，联邦解决"数据不能集中" |
| SL ⊕ 联邦             | **SplitFed**：客户端并行前向，服务器侧再做一次 FedAvg     | 你若要出 SplitFed 基线，就是这种叠加   |
| 迁移 ⊕ 联邦 ⊕ 个性化       | FedVLA 的 stem/head 本地化、只聚合 trunk        | 底层共享知识、表层适配各自的机器人本体       |
| 迁移 ⊕ 通信             | 先看通道质量再决定这一轮传多少层/多少比特                    | 这是你能做通信贡献的入口              |

### 0.7.5 对你选题的三条结论

1. **"用了预训练权重"不构成创新点。** 迁移学习在这里是**工程前置条件**（让 8GB 显存的小模型在仿真里能收敛），写在实验设置里，不要写进创新点列表。创新点必须落在"多方协同时的那些通信动作"上。
2. **单独做迁移学习撑不起通信学科归属。** 迁移的故事里没有信道、没有时延、没有丢包，答辩委员会会问"这跟通信有什么关系"。只有联邦或 split learning 能把"链路条件 → 训练收敛/控制性能"这条因果链立起来。
3. **最稳的讲法是三层递进**：① 先有预训练（迁移，工程前提）→ ② 再做联邦或分割的多方协同（主战场，通信在这里）→ ③ 通信约束（带宽/时延/丢包）如何改变①和②的效果（你的贡献）。

# 第一部分：Split Learning for VLA

## 1. 它是什么

模型按层切开，客户端只跑前几层，把中间激活（smashed data）发给服务器，服务器跑剩下的层、算损失、把梯度传回来，客户端用回传的梯度更新自己的浅层参数。

三种常见变体：

| 变体                     | 特点                                 | 你的适配度                                     |
| ---------------------- | ---------------------------------- | ----------------------------------------- |
| Vanilla Split Learning | 客户端**轮流**训练，一个训完传给下一个              | 慢，且非 iid 下效果差，不推荐                         |
| **SplitFed（SFL）**      | 客户端**并行**各自前向，服务器侧并行训练并做 FedAvg 聚合 | **推荐**。并行快，且能和 FedAvg / FedProx 等联邦基线公平比较 |
| U-shaped SL            | 首尾都在客户端，标签也不上传，隐私最强                | 实现最复杂，但隐私卖点最足，可作为额外一档对比                   |

推荐走 **SplitFed**：结构上它天然包含"客户端侧模型 + 服务器侧模型"，你能在同一套代码里同时跑联邦基线，实验对比最省事。

## 2. 实现要点（其实不神秘）

把 HPT 拆成两个 `nn.Module`：

```
client_side = stem + trunk[:cut]        # 客户端
server_side = trunk[cut:] + head        # 服务器
```

训练一步的伪代码逻辑：

```python
# 客户端
act = client_side(obs)                  # 前向到切分层
send(act.detach())                      # 上行：只传激活，不传原始数据
# 服务器
out = server_side(act)                  # 需要 act 带梯度图，用 act.requires_grad_()
loss = criterion(out, action_gt)
loss.backward()
send(act.grad)                          # 下行：回传切分层梯度
# 客户端
act.backward(gradient=act.grad)         # 用收到的梯度继续反传
opt_client.step(); opt_server.step()
```

单机串行仿真时，两个"端"都在同一进程里，直接传张量即可，不需要真的写网络通信。真正的实现工作量大约在 **100–200 行**，难点在梯度图的衔接（`act.requires_grad_()` 与 `act.backward(gradient=...)`），不是算法难度。

## 3. 通信侧该写什么（一个必须纠正的误解）

**Split learning 的总通信量通常远大于联邦学习**——联邦学习一轮只传一次模型更新，split learning 每个 batch 都要传激活和梯度。所以：

- ❌ 不要把它写成"省通信的方案"，那是错的，会被评委一句话问倒
- ✅ 它的卖点是：**客户端算力与显存压力小、模型权重不共享、原始数据与标签都不出端**
- ✅ 而**代价**是频繁传输 → 所以压缩与量化成为真问题 → **这正好是通信侧的研究内容**

于是论文的通信侧故事应该是：

> 切分点选择与激活压缩的联合优化：在给定带宽与时延约束下，如何选切分点、如何压缩激活，使训练收敛与最终成功率最优。

这是一个货真价实的通信优化问题，且机器人侧的实验是真的。

## 4. 隐私侧：特征反演比梯度反演更直观

上传的是中间激活，攻击者（服务器）可以直接从激活重建输入图像。

- **浅层切分**：激活仍保留大量像素级信息，重建质量高，几乎能还原原始画面
- **深层切分**：像素细节丢失，但语义信息（场景布局、有无人物、操作对象）仍可能泄露

这形成一个干净的可研究权衡：**切分点 vs 通信量 vs 隐私泄露**的三维扫描。而且重建图像的对比图是可视化的，评委一眼能看懂——比梯度反演的模糊图直观得多。

## 5. 8GB 单机仿真下的诚实说明

在**单机串行仿真**中，split learning 的显存优势**不能完全体现**：因为 trunk 照样要在这张卡上跑，总参数量没变。

真实存在的两点优势：

- 客户端侧只保留浅层激活，深层激活在服务器侧，**峰值激活显存更低**（前向完可释放）
- 客户端侧不需要存完整模型的优化器状态

但这两点在单机串行下是次要的。**所以论文里应该把"客户端资源受限"作为系统设定的合理性论证，而不是靠本地实测去证明显存优势**——本地实测要展示的是通信、隐私与收敛的权衡。这个区分很重要，别搞反了。

## 6. 实验设计清单

| 实验组   | 自变量                                                | 因变量              |
| ----- | -------------------------------------------------- | ---------------- |
| 切分点扫描 | 切在第 1/2/3 层                                        | 上行数据量、收敛速度、最终成功率 |
| 压缩扫描  | 激活量化位宽（32/16/8/4 bit）、稀疏化比例                        | 成功率损失 vs 上行量下降   |
| 丢包注入  | 丢包率 0 / 5% / 10% / 20%，三种补救策略（重传 / 跳过该步 / 复用上一步激活） | 收敛稳定性、成功率        |
| 特征反演  | 各切分点下的重建图像质量（PSNR / 视觉对比）                          | 泄露程度             |
| 基线对比  | FedAvg / FedProx / SplitFed / 你的方案                 | 成功率 + 总上行字节数     |

**丢包这一组是 split learning 独有的、联邦学习没有的研究点**——丢一个 batch 的激活会导致该步前向断链，怎么处理是有讲究的，而且没有标准答案。

## 7. 难度与风险

- **难度 4/5**：比联邦学习多出跨切分梯度回传，第一周会卡在梯度图上
- **最大风险**：训练不稳定。切分后客户端侧的学习率与服务器侧不同步，容易出现一端崩掉
- **缓解**：先用最浅的切分点（客户端只有 stem，且冻结）跑通，确认能收敛后再放开训练
- **建议定位**：作为联邦 VLA 主线的**加强包**（另一章或一节），而不是换主线

# 第二部分：边云协同 VLA 推理

## 1. 它是什么

不训练，只推理。VLA 模型切开：边缘侧（机器人本地或近端边缘服务器）跑视觉编码等前几层，云端跑剩下的重型部分，中间通过无线链路传中间特征。

研究问题变成：**在带宽、时延、算力的约束下，怎么切、怎么调度，才能让机器人控制性能最好。**

## 2. 时延构成

```
T_total = T_边缘计算 + T_上行(数据量/带宽) + T_云端计算 + T_下行 + T_排队
```

每一项都能测或能建模：计算时延在单机上实测计时即可，传输时延用带宽公式算，排队可以用简单的排队模型或直接注入。

## 3. 关键：它跟闭环控制的实时性打架

这是这个方向**最有价值的地方**，也是它区别于纯通信论文的地方：

机器人按固定控制频率索取动作（常见量级在几 Hz 到几十 Hz）。如果 `T_total` 超过控制周期，机器人拿不到当期动作，只能沿用上一拍的输出——动作就"旧了"。

于是：

- 横轴：端到端时延（或带宽，通信变量）
- 纵轴：任务成功率（机器人指标）
- 曲线形状：在某个临界点之后成功率快速跌落

**这张图同时说服通信评委和机器人评委，是这个方向最值钱的产出。**

## 4. 最便宜也最有说服力的实验

**人为延迟动作若干步，看成功率怎么掉。**

在 Meta-World 里跑闭环，把策略输出的动作缓存 k 步再执行（模拟端到端时延 k 个控制周期），扫 k = 0, 1, 2, 3, 5, 10。

- 成本：不需要网络、不需要两台机器、不需要训练，只要能跑闭环推理
- 真实性：这是真的闭环退化，不是编造的 
- 说服力：曲线出来就很直观

再加上**动作分块**（action chunking，一次预测多步动作、边执行边算下一步，是 ACT / RT-1 / OpenVLA 一类模型的常见做法）作为缓解手段，可以研究：

> **动作分块长度 vs 可容忍时延的权衡**——分块越长越抗时延，但对动态环境的响应越迟钝。

这是一个真实的、两侧都成立的 trade-off，而且论文里可以形式化成一个优化问题。

## 5. 通信侧怎么写才撑得起硕士论文

只画一条"时延 vs 成功率"曲线是不够的，要把它形式化：

> 在带宽与算力约束下，联合优化切分点、动作分块长度与多机器人调度策略，最大化闭环控制性能（成功率）。

三个决策变量、一个约束、一个目标——这就是通信评委熟悉的优化问题形态。多机器人共享边缘服务器时还能加排队与调度，内容量就够了。

## 6. 8GB 能跑什么模型

- **HPT-Base / Large**：推理非常轻松，推荐
- OpenVLA-7B 这类：8GB 跑 fp16 推理偏紧，需要量化，且慢，不建议作为主力
- 结论：用 HPT 系列，把重点放在切分与调度上，而不是模型规模上

## 7. 难度与风险

- **难度 2/5**：不训练、不调收敛，只要跑通推理闭环 + 注入时延 + 统计成功率
- **最大的优点**：第 1 月就能出图，正反馈来得早，放养状态下这点很重要
- **最大的缺点**：**学不到训练管线**。简历上写的是"推理与部署"，不是"策略训练"。如果目标是算法研究岗，分量不足；如果是部署/工程岗，正好对口
- **创新点偏薄的风险**：需要把优化问题形式化，否则会显得像"测了一条曲线"
- **红线**：如果只测时延不测成功率，就退化成纯通信论文了。**纵轴必须是成功率，闭环必须真的跑起来**

# 第三部分：怎么选，以及能不能都要

## 决策点只有一个：你想去哪种岗位

| 目标岗位                   | 建议                            |
| ---------------------- | ----------------------------- |
| 算法研究岗（策略学习、VLA 训练）     | 联邦 VLA 主线，split learning 作加强包 |
| 部署 / 工程岗（模型上板、时延优化、系统） | 边云协同，难度最低且直接对口                |
| 还没想清楚                  | 联邦 VLA 主线 + 边云推理作为一章          |

## 可以都要，而且成本不高

边云推理那一组实验**不需要训练**，第 4 月顺手就能加：用联邦训练出来的模型跑闭环，注入时延，画成功率曲线。

这样论文的结构变成：

- 第 4 章：训练侧（联邦 / split learning 的聚合与压缩）
- 第 5 章：推理侧（边云切分与时延下的控制性能）

**训练 + 推理全生命周期**，内容量对硕士论文来说非常充足，而且两章的通信侧都站得住。这是我个人最推荐的组合——前提是你的进度到第 4 月时还健康，如果有压力就砍掉推理那一章，砍了不影响主干。
