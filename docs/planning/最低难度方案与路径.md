# 最低难度方案：联邦 VLA 的聚合策略与隐私防护

> 约束：通信硕士（导师放养）、RIS 本科背景、纯仿真、真机资源少、目标是转机器人就业。
> 目标：在满足硕士论文四条硬门槛的前提下，把工程风险压到最低。

## 1. 方案一句话

**不动模型结构，只动聚合层。** 用简化的 top-k MoE 替代双门控 MoE，复现 FedVLA 的专家驱动聚合（EDA）思想，验证"EDA 在均衡异构划分下退化为 FedAvg"这个假设，然后提出按簇聚合作为改进，并在无线损伤与隐私攻击两个场景下验证——后两块正是你 RIS 背景的主场。

## 2. 五个降难度决策，以及各自省掉了什么

| 决策 | 省掉的东西 |
|---|---|
| **用 top-k MoE，不用双门控** | 双门控的专家自感知参数 `W_e` 与阈值 λ 是最容易训崩的环节（本仓库 toy 实验已显示：初始化尺度不对时要么全激活、要么几乎不激活）。top-k 是标准实现，专家选择计数照样能拿到，EDA 照样能跑 |
| **用 HPT 预训练权重微调，不从零训** | 训练时间与算力需求大幅下降，也基本消除"训不出来"的风险 |
| **用 Flower 搭联邦，不自写** | 客户端调度、序列化、聚合接口这些工程活，省一到两周 |
| **客户端串行时间片模拟，不用多卡** | 联邦仿真的常规做法，结果等价，不需要 N 张卡 |
| **无线用"丢包 + 时延注入"，不用 3GPP 全套信道模型** | 不需要信道仿真器。在聚合前按概率丢弃客户端更新、给更新加 staleness 即可。代价是要在论文里明确声明这是简化模型 |

## 3. 技术选型（每一项都按"最省事"选）

| 组件 | 选择 | 理由 |
|---|---|---|
| 仿真环境 | **Meta-World**（MuJoCo） | pip 可装，MuJoCo 官方支持 Windows（你是 win32）；FedVLA 原文平台，口径可对齐。LIBERO 依赖更重，RLBench 要 CoppeliaSim，在 Windows 上更麻烦 |
| 主干 | **HPT-Base（12.6M）+ 预训练权重** | 比 OpenVLA 7B 小两个数量级；LoRA 或全参微调都跑得动 |
| MoE | **标准 top-k（k=2）** | 避开双门控调参 |
| 联邦框架 | **Flower** | PyTorch 集成现成 |
| 客户端数 | 4–8 个，串行模拟 | 足够体现异构，评估成本可控 |
| 任务数 | Meta-World 的 3–5 个任务 | 不要一上来做 20 个 |
| 无线损伤 | 丢包率 + staleness 注入 | 两三个参数就能做完整扫描 |
| 隐私 | DP-SGD 加噪（Opacus 现成）+ 梯度反演攻击 | 攻击有开源实现可借鉴，不必从零写 |
| 统计 | 3 seeds × 每客户端 20 rollouts | 硕士水平的最低要求，不能少 |

## 4. 论文故事线

**一句话主论点**

> 现有专家驱动的联邦 VLA 聚合在客户端任务均衡划分下会退化为普通 FedAvg；本文提出按任务簇的自适应聚合，并在上行链路损伤与梯度泄露威胁下验证其优于统一防护方案。

**三个可证伪假设**（对应硕士论文的创新点要求）

- **H1**：在均衡分簇的非 iid 划分下，EDA 相对 FedAvg 的增益在统计上不显著。
- **H2**：按簇聚合在该设定下显著优于 EDA 与 FedAvg。
- **H3**：视觉 / 语言 / 动作三条通路对隐私泄露与压缩的敏感度不同，统一 DP 预算劣于模态感知预算。

**这套故事的关键优势**：H1 无论被证实还是被推翻，都是一个可以写进论文的结果。这把"跑不出预期增益"从失败变成了产出。

## 5. 六个月路径与三道门禁

### 第 1 月：环境 + 单机行为克隆

- 装 MuJoCo + Meta-World，跑通内置示例
- 下载 HPT-Base 权重，微调单任务行为克隆
- 记录显存占用与每 epoch 耗时（**这是你后面所有排期的基础，别跳过**）
- **门 1**：单任务成功率达到可用水平（明显超过随机策略，量级接近 HPT 公开报告）
- 门 1 过不了：先用更多示范数据或更长训练；超过 3 周仍装不起来 → 启用 Plan B

### 第 2 月：联邦框架 + FedAvg 基线

- Flower 搭起联邦流程，4 客户端
- 做任务级非 iid 划分，对比集中式训练
- **门 2**：FedAvg 在非 iid 下明显低于集中式（复现"异构有害"这个前提）
- 门 2 过不了：把每客户端任务数降到 1–2，加大异构程度

### 第 3 月：简化 MoE + EDA 复现与判定

- 在 trunk 里加 top-k MoE，统计专家选择计数矩阵
- 实现 EDA（本仓库 `fl_core.py` 的 `eda_weights` 直接可用）
- 跑"均衡两簇"与"含孤立客户端"两种划分
- **门 3**：H1 可被判定（证实或推翻都算过）
- **这是整个方案风险最低的一环**——不存在"白跑了"的可能

### 第 4 月：改进 + 通信与隐私（你的主场）

- 实现按簇聚合（对专家选择向量做聚类，簇内聚合），验证 H2
- 加无线场景：丢包率扫描 + staleness 处理
- 加隐私场景：DP-SGD 加噪 + 梯度反演攻击，验证 H3

### 第 5 月：完整实验 + 消融

- 五个基线：Centralized / FedAvg / FedProx / SCAFFOLD / EDA / 你的方法
- 消融：聚类数、丢包率、DP 预算分配方式
- 3 seeds × 20 rollouts，报均值与置信区间
- 算力不够就缩任务子集，**但绝不减 seed**

### 第 6 月：写作

- 第 3 章系统模型（联邦训练 + 上行链路 + 威胁模型）是答辩安全的锚点
- 明确声明仿真的简化：IOSP 用了仿真器真值、无线用简化注入模型、无真机验证

## 6. Plan B：环境实在装不起来时的降级方案

如果第 1 月超过 3 周仍搞不定 MuJoCo，切到**离线数据集 + 联邦行为克隆**：

- 用已公开的操作数据集做离线 BC，完全不需要仿真器
- 主指标改为验证集动作预测误差 / 离线评估指标
- 代价：没有成功率，机器人侧的说服力明显下降；必须靠通信与隐私侧的完整性补上
- 判断标准：如果答辩委员会是通信学科且侧重联邦学习部分，Plan B 仍可过；如果要求机器人操作性能，Plan B 风险很大

**Plan B 是保底，不要一开始就选它。**

## 7. 这个方案给你的就业价值

能拿到手的：PyTorch、Transformer 策略网络微调、模仿学习、MuJoCo、多模态 VLA、分布式训练流程、联邦学习与隐私工程。

## 8. 8GB 显存下的定版配置

### 8.1 一个重要的降风险发现

HPT 官方仓库**自带 Meta-World 的训练与测试脚本**（`experiments/scripts/metaworld/` 下有 `train_test_metaworld_1task.sh` 与 `train_test_metaworld_20task_finetune.sh`），并且支持直接从 HuggingFace 加载权重（`hf://liruiw/hpt-base`）。

这意味着**第 1 月的数据管线和训练循环不用你自己写**，改配置和路径即可。原方案里"模仿学习 4/5 难度"这一项可以直接降到 2/5。这是整个方案里最大的一次风险削减，先去把那两个脚本跑通。

### 8.2 定死的参数（8GB）

| 项 | 取值 | 理由 |
|---|---|---|
| 主干 | **HPT-Base 12.6M**（OOM 就降 Small 3.1M） | 8GB 下 Base 很宽裕，瓶颈在激活值不在参数量 |
| 训练范围 | **冻结 stem，只训 trunk + action head** | 省显存也省算力；且与 FedVLA「stem 与 head 个性化、只聚合 trunk」的设定完全一致，不影响方法正确性 |
| 精度 | **AMP（bf16/fp16）默认开启** | 激活值显存大约减半 |
| Batch | **16**，OOM 降到 8 + 梯度累积 2 | 先跑通再往上试 |
| 图像分辨率 | **84×84**（Meta-World 默认），不要用 224 | 视觉 stem 已冻结，分辨率直接决定激活值大小 |
| MoE 布置 | **只在一半层放 MoE**（如 4 层中的 2 层），专家数 8，top-k=2 | 全层放会让参数与显存翻倍；EDA 只需要每层的专家计数，层数少反而更好分析 |
| 客户端数 | **4 个，串行模拟** | 一次只有一个模型在 GPU 上；服务器聚合放 CPU。N 个客户端不增加显存 |
| 通信轮数 | 50 轮 × 3 本地 epoch（先跑通，再按需加） | 8GB 卡的算力通常也偏弱，总时长线性增长 |
| 任务数 | 3 个 | 评估成本线性，先小后大 |

**上行载荷**（正好是你通信实验的素材）：trunk 12.6M 参数，FP32 约 **50.4 MB/客户端/轮**，4 客户端约 201.6 MB/轮；量化到 FP16 约 25.2 MB。丢包率与压缩比的扫描可以直接在这个量级上设。

### 8.3 第 1 周：30 分钟冒烟测试，把排期基数测出来

不要信任何人的时间估算，包括论文和我的。先测这四个数：

| 项 | 怎么测 |
|---|---|
| 单卡单 epoch 训练耗时 | 用 HPT 的 1task 脚本跑 3 个 epoch 取平均 |
| 训练显存峰值 | `torch.cuda.max_memory_allocated()`，写进日志 |
| 一次 rollout 耗时 | 含环境步进，跑 10 次取平均 |
| 一次 trunk 上传+聚合耗时 | 计时即可，用于估算通信实验开销 |

然后按这个公式排期（把数字填进去）：

```
单轮训练时间 = 客户端数 × 本地 epoch 数 × 单 epoch 耗时 + 聚合耗时
总训练时间   = 单轮训练时间 × 轮数
一次完整评估 = 客户端数 × rollout 数 × 单次 rollout 耗时
完整实验     = 总训练时间 × 配置数 + 一次完整评估 × 配置数 × seed 数
```

第 5 月的 3 seeds 能不能跑完，取决于这张表——**第一周就要算出来，不要等到第 5 月才发现跑不完**。

### 8.4 8GB 的三条警戒线

1. **显存峰值 > 7.0 GB** → batch 降到 8 + 梯度累积 2
2. **仍 OOM** → 确认 stem 已冻结；再不行换 HPT-Small
3. **单轮训练 > 30 分钟** → 减本地 epoch 或减任务数，**不要减轮数**（轮数影响收敛，减了结果不可信）

### 8.5 Windows 上的一个已知摩擦点

你是 win32，MuJoCo 在 Windows 上能装，但**离屏渲染**是个常见坑：Linux 上常用 `MUJOCO_GL=osmesa` 或 `egl`，Windows 上未必可用。

建议顺序：
1. 优先装 **WSL2 + Ubuntu** 跑 MuJoCo 与 Meta-World，依赖和文档都按 Linux 走，坑最少
2. 必须原生 Windows 的话，先试 `MUJOCO_GL=osmesa`；失败就用 `glfw`（会弹窗口，但能跑）
3. 第 1 月超过 3 周仍卡在环境上 → 启用 Plan B，不要耗下去

**把显存峰值、每 epoch 耗时这些数记进日志**，它们后面会变成论文里"实验环境与可复现性"一节的内容，不要等写论文时再补。
