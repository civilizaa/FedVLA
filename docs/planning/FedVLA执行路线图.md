# FedVLA 执行路线图：从零到论文成型

> **约束**：通信硕士、导师放养、委员会以通信为主、不要求论文等级、纯仿真。  
> **硬件**：Windows + 单卡 8GB 显存。  
> **目标**：24 周产出一篇满足硕士四条硬门槛的论文，同时拿到机器人学习全栈能力。

**一句话方案**：不动模型结构，只动聚合层。用 HPT 预训练权重 + Meta-World 仿真，复现并检验 FedVLA 的专家驱动聚合（EDA），提出按簇聚合改进，在上行链路损伤与梯度泄露两个场景下验证——后两块是你 RIS 背景的主场。

## 2. 第 1 阶段（第 1–4 周）：环境与单机行为克隆

### 2.1 先说一个硬结论：必须用 WSL2

我核过了 HPT 官方仓库的依赖，结论比预想的强硬：

- `pyproject.toml` 里钉着 **`mujoco-py`**（MuJoCo 2.1 时代的 Python 绑定，需本地编译，**不支持 Windows**）
- 钉着 `numpy==1.24.3`、`torch==2.1.1`、`Cython==0.29.36`、`gym==0.26.2`
- Meta-World 官方（3.1.1）声明**只测试 Linux 与 macOS，不接受 Windows**

**原生 Windows 基本走不通，别在这一步耗两周。** 直接装 WSL2 + Ubuntu 22.04。

> WSL2 里**不要装 Linux 版 NVIDIA 驱动**——用 Windows 宿主机驱动即可，WSL2 支持 GPU 直通。装了反而冲突。

### 2.2 安装顺序（在 WSL2 的 Ubuntu 里执行）

```bash
# 1. 基础环境
conda create -n hpt python=3.10 -y && conda activate hpt

# 2. MuJoCo 2.1.0（HPT README 原样）
mkdir -p ~/.mujoco && cd ~/.mujoco
wget https://mujoco.org/download/mujoco210-linux-x86_64.tar.gz -O mujoco210.tar.gz --no-check-certificate
tar -xvzf mujoco210.tar.gz
cat >> ~/.bashrc <<'EOF'
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$HOME/.mujoco/mujoco210/bin
export MUJOCO_GL=egl
EOF
source ~/.bashrc

# 3. 拉代码
git clone https://github.com/liruiw/HPT.git && cd HPT

# 4. 装依赖（关键：不要直接 pip install -e .）
pip install -e . --no-deps
pip install "numpy==1.24.3" "torch==2.1.1" "torchvision==0.16.1" \
  "gym==0.26.2" "gymnasium>=0.29.0" "mujoco-py" "Cython==0.29.36" \
  "hydra-core==1.3.2" "hydra-joblib-launcher" "einops==0.7.0" "timm==0.9.12" \
  "transformers==4.36.0" "scikit-learn==1.3.2" "matplotlib==3.7.4" \
  "seaborn==0.13.0" "opencv-python==4.8.1.78" "imageio==2.27.0" \
  "tqdm==4.66.1" "tabulate==0.9.0" "easydict==1.11" "transforms3d==0.4.1" \
  "wandb==0.16.1" "scipy==1.10.1" "lxml==4.9.3" "GPUtil==1.4.0"

# 5. wandb 离线跑，别让它卡住你
export WANDB_MODE=offline
```

**第 4 步为什么这么写**：`pip install -e .` 会连带拉 `tensorflow==2.13.1`、`rlds`、`dm-reverb`、`zarr`、`ray`、`tfp-nightly`——这些是 RLDS 数据管线用的，重且极易版本冲突。你只需要跑 Meta-World 的脚本，**先跳过**。等脚本真正报缺某个包再单独补。

### 2.3 第一次冒烟（目标：30 分钟内看到结果）

```bash
# 先看 debug 模式能不能跑起来（小数据、少步数）
python -m hpt.run env=mujoco_metaworld domains=mujoco_metaworld_task1 \
  +datasetsize=metaworld_1 dataset.episode_cnt=100 \
  train.pretrained_dir=hf://liruiw/hpt-base +mode=debug
```

两个坑，先知道：

- 官方 `train_test_metaworld_1task.sh` 里把 `train.pretrained_dir` 拼成了 `output/$PRETRAINED`（即 `output/hf://...`）。**建议直接用上面的命令行，显式覆盖该参数**，别被脚本的默认拼接坑住。
- 评估脚本默认 `seed="range(3)"` 且 `hydra.launcher.n_jobs=3`（3 个进程并行）。8GB 卡上**先改成 1**，跑通再并行。

```bash
python -m hpt.run_eval --multirun --config-name=config \
  --config-path=../output/<上面的输出目录> \
  train.pretrained_dir="'output/<输出目录>'" \
  seed="range(1)" hydra/launcher=joblib hydra.launcher.n_jobs=1
```

### 2.4 四个实测数（第 1 周必须拿到）

| 项                | 怎么测                                      |
| ---------------- | ---------------------------------------- |
| 单卡单 epoch 训练耗时   | 跑 3 个 epoch 取平均                          |
| 训练显存峰值           | `torch.cuda.max_memory_allocated()`，写进日志 |
| 单次 rollout 耗时    | 含环境步进，跑 10 次取平均                          |
| 一次 trunk 上传+聚合耗时 | 直接计时                                     |

填进这个公式，算出第 5 阶段跑不跑得完：

```
单轮训练时间 = 客户端数 × 本地 epoch 数 × 单 epoch 耗时 + 聚合耗时
总训练时间   = 单轮训练时间 × 轮数
一次完整评估 = 客户端数 × rollout 数 × 单次 rollout 耗时
完整实验耗时 = 总训练时间 × 配置数 + 一次完整评估 × 配置数 × seed 数
```

**第 1 周算不出来，第 17 周就会崩。** 这些数字同时是你论文"实验环境与可复现性"一节的内容，别等写论文再补。

### 2.5 门 1（第 4 周末）

- **通过标准**：单任务成功率明显超过随机策略，且与 HPT 官方报告的同任务数字在同一量级（允许差 15–20 个百分点，因为你的配置被裁剪过）
- **不通过**：先加示范数据（episode_cnt 从 100 加到 200–500）或延长训练；**超过 3 周仍卡在环境上 → 启用 Plan B**
- **Plan B**：离线数据集 + 联邦行为克隆，主指标改成动作预测误差。代价是没有成功率，说服力明显下降，只能靠通信与隐私侧补

## 3. 第 2 阶段（第 5–8 周）：联邦框架与基线

### 3.1 做什么

- 用 Flower 搭联邦流程（客户端调度、序列化省一到两周），或者直接用你已有的 `fedvla_scaffold/fl_core.py` 手写最小循环——**先手写跑通一轮，再决定要不要上 Flower**。4 客户端串行模拟，一次只有一个模型在 GPU 上。
- 任务级非 iid 划分：4 个客户端分 3 个 Meta-World 任务，构造"每客户端 1–2 个任务"的异构。
- 基线：集中式训练（上界）、FedAvg。

### 3.2 门 2（第 8 周末）

- **通过标准**：FedAvg 在非 iid 下明显低于集中式——复现"异构有害"这个前提。没有这个gap，后面所有"改进"都无从谈起。
- **不通过**：把每客户端任务数降到 1，加大异构程度；或增加本地 epoch 数放大漂移。

### 3.3 这一阶段的隐藏收获

把 trunk 上传的真实字节数记下来。HPT-Base 12.6M 参数，FP32 约 **50.4 MB/客户端/轮**，4 客户端约 201.6 MB/轮。这个数是你第 4 阶段所有通信实验的锚点——**论文里"我们的方法把上行量降到 X MB"这句话，必须基于实测，不能基于估算**。

---

## 4. 第 3 阶段（第 9–12 周）：MoE + EDA 判定

### 4.1 做什么

- 在 trunk 里加标准 **top-k MoE（专家数 8，k=2，只放一半层）**。不要用 FedVLA 的双门控——`W_e` 与 λ 的初始化尺度不对时，要么全激活要么几乎不激活（已在 toy 实验里观察到），是这个方案里最容易训崩的环节。
- 统计每层的专家选择计数矩阵，直接套 `fl_core.py` 里的 `eda_weights` 实现 EDA。
- 跑两种划分：**均衡两簇** vs **含孤立客户端**。

### 4.2 门 3（第 12 周末）

- **通过标准**：H1（均衡划分下 EDA 相对 FedAvg 增益不显著）被证实或被推翻。**两者都算过**。
- 如果被推翻（EDA 确实显著更好），你的论文故事就变成"在 X 设定下 EDA 有效，但在 Y 设定下退化"——照样成立，且更有层次。

### 4.3 一个已经发现的坑，别踩

toy 实验显示 EDA 的权重 `w_i ∝ Σ_j s_ij` 衡量的是**中心性**，不是簇归属。横跨两个簇的客户端反而拿到最高权重。写论文时不要把 EDA 描述成"簇内加权"——它的实际行为是"越像大家，权重越大"。这本身就是可写的一条发现。

## 5. 第 4 阶段（第 13–16 周）：通信与隐私（你的主场）

### 5.1 三条曲线，都是"横轴通信参数、纵轴成功率"

| 实验   | 横轴                                        | 说明             |
| ---- | ----------------------------------------- | -------------- |
| 丢包扫描 | 丢包率 0 / 5 / 10 / 20%                      | 上行更新按概率丢弃      |
| 压缩扫描 | 压缩比（FP32 → FP16 → 1-2 bit 量化 / top-1% 稀疏） | **最稳的一条曲线**    |
| 流量预算 | 总上行预算（如 2 GB）内的收敛速度                       | 比丢包更敏感，工程上也更真实 |
| 隐私预算 | ε（DP-SGD 加噪，Opacus 现成）                    | 配梯度反演攻击的可视化    |

再加一条 staleness（时延导致的过期更新）实验，用"跳过 / 复用上一步"两种补救对比。

### 5.2 隐私侧

DP-SGD 加噪 + 梯度反演攻击（有开源实现可借鉴）。**视觉 / 语言 / 动作三条通路分别测敏感度**，验证 H3：统一 DP 预算劣于模态感知预算。攻击重建出来的图是论文里最直观的一张图，别省。

### 5.3 第 14 周的判据（重要）

丢包扫描做完后看幅度：

- 成功率变化 **> 5 个百分点**（明显超出 3 seeds 噪声带）→ 通信故事立得住，继续
- 变化 **< 2 个百分点** → 联邦学习每轮只传一次，链路损伤被多轮平均稀释了。**先试两个补救**（极端压缩曲线、流量预算曲线），都出不来才考虑转 Split Learning

## 6. 第 5 阶段（第 17–20 周）：完整实验与消融

### 6.1 主实验矩阵

| 方法              | 均衡划分 | 含孤立客户端 |
| --------------- | ---- | ------ |
| Centralized（上界） | ✓    | —      |
| FedAvg          | ✓    | ✓      |
| FedProx         | ✓    | ✓      |
| SCAFFOLD        | ✓    | ✓      |
| EDA（复现）         | ✓    | ✓      |
| **按簇聚合（你的）**    | ✓    | ✓      |

每格 3 seeds × 每客户端 20 rollouts，报均值 ± 置信区间。

### 6.2 消融清单

聚类数、MoE 层数与专家数、丢包率、DP 预算分配方式、本地 epoch 数。

### 6.3 可选：SplitFed 扩展（第 10 节的 2 周）

如果主实验提前跑完，用同一套模型加一个 SplitFed 变体作为第 7 个对比方法。复用度高，只新增切分与梯度回传。收益是通信味道更足（激活压缩、丢包断链、特征反演三张图），且 SL+VLA 这块 scoop 风险低。**但它是加分项，不是必做项。**

- 符号表、假设列表、优化问题的形式化表述

### 7.2 三条讲述原则（面向通信委员会）

1. **图的横轴选通信参数**：丢包率 / 信噪比 / 压缩比 / ε，纵轴任务成功率。一张图说服两个学科。避免"横轴训练轮数"——通信评委看不到自己的问题。
2. **成功率当因变量，不是研究对象**：明确写"所有方法在同一框架、同一骨干、同一数据下比较，绝对成功率不是本文贡献"。顺带回避"没有真机"的质疑。
3. **题目措辞偏通信**：推荐《无线网络中联邦视觉-语言-动作学习的聚合策略与隐私保护研究》，避免《基于专家混合的机器人操作策略研究》。

### 7.3 必须诚实声明的三条简化

IOSP 用了仿真器真值、无线用丢包/staleness 注入而非 3GPP 全套、无真机验证。**主动写出来比被问出来好一百倍。**

## 附录 A：8GB 定版配置

| 项     | 取值                                 |
| ----- | ---------------------------------- |
| 主干    | HPT-Base 12.6M（OOM 降 Small 3.1M）   |
| 训练范围  | **冻结 stem，只训 trunk + action head** |
| 精度    | AMP（bf16/fp16）默认开                  |
| Batch | 16，OOM 降到 8 + 梯度累积 2               |
| 图像    | 84×84（不要用 224）                     |
| MoE   | 只在一半层放，专家数 8，top-k=2               |
| 客户端   | 4 个，串行模拟（聚合放 CPU，不额外占显存）           |
| 轮数    | 50 轮 × 3 本地 epoch                  |
| 任务    | Meta-World 3 个任务                   |
| 统计    | 3 seeds × 20 rollouts              |

冻结 stem 还有个额外好处：它与 FedVLA"stem 与 head 个性化、只聚合 trunk"的设定完全一致，不影响方法正确性。

### 三条警戒线

1. 显存峰值 > 7.0 GB → batch 降到 8 + 梯度累积 2
2. 仍 OOM → 确认 stem 已冻结；再不行换 HPT-Small
3. 单轮训练 > 30 分钟 → 减本地 epoch 或减任务数，**不要减轮数**

## 附录 B：统计规范（硕士水平的底线）

- **≥3 seeds**，每个配置每 seed 独立评估 **≥20 rollouts**
- 报均值 ± 95% 置信区间，不要只报最好那次
- 显著性检验：两套方法比较至少给 t-test 或 bootstrap 区间
- 所有曲线必须带误差带，误差带宽度本身就是结论（跳不出噪声带的"增益"不算增益）

| 两边都做浅         | 月度自评连续两月某条硬门槛无进展    | 缩范围，不要继续堆模块               |
